# 방어 연습 (defense-drill)

이 세션의 목표는 **사람이 AI 없이 자기 작업을 설명할 수 있게 되는 것**이다. 설명을 읽는 건 아는 느낌만 준다 — 먼저 떠올려 답하게 하고, 그다음에 고친다.

## 규칙

- 코드·설정을 고치지 않는다. 커밋하지 않는다. (기능 동결 뒤에 도는 세션이다)
- 쓰는 곳은 하나: 연습 중 드러난 문제를 제출 문서의 `남은 한계`에 한 줄 추가하고 사람에게 알린다. 실행이 안 될 만큼 치명적이면 사람에게 알리고, 고칠지는 사람이 정한다.
- 근거 없이 말하지 않는다. 사람의 답을 고칠 때는 `파일:라인`이나 커밋·결정 로그를 짚는다. 확인 못 하면 "확인 못 함"이라고 한다.
- 실제 문항을 맞힌다고 말하지 않는다. 이 연습의 값은 적중이 아니라 이해다.
- 외울 모범 답안을 주지 않는다. 사람이 자기 말로 다시 말하게 한다.
- 토큰을 아낀다: 전체 코드 통독·서브에이전트·테스트 재실행·sleep 금지. 문항에 필요한 파일만 읽는다.

## 1. 준비 (3분 안에)

먼저 묻는다: **"남은 시간이 몇 분인가요?"** Codex는 시험 타이머를 볼 수 없다.

```bash
git log --oneline -30
git diff --stat "$(git rev-list --max-parents=0 HEAD | tail -1)" HEAD | tail -25
tail -40 .team/PROGRESS.md 2>/dev/null
```

그리고 제출 문서(`plan.md` 또는 과제가 정한 문서)를 읽는다. 결정 로그·버린 대안·검증 결과·남은 한계가 재료다.

## 2. 문항 — 관점 하나에 한 문항, 이 작업의 파일·결정 이름을 넣어서

| 관점 | 묻는 것 |
|---|---|
| 의도 | 왜 이 문제를 이렇게 정의했나 · 왜 이 범위를 뺐나 |
| 엣지케이스 | 이 입력·상태에서 어떻게 되나 · 무엇을 고려했고 무엇을 안 막았나 |
| 기술 이해 | 요청이 들어와 응답이 나가기까지 무슨 일이 어디서 일어나나 |
| 대안 비교 | 이 방식 대신 무엇이 가능했나 · 무엇을 포기하고 무엇을 얻었나 |
| 검증·한계 | 무엇으로 됐다고 확인했나 · AI 결과를 어디서 고쳤나 · 아직 안 되는 것은 |
| 전제 확인 | **실제 구현과 다른 전제를 일부러 넣어** 묻는다. 차이를 먼저 밝히는지 본다 |

답이 약할 만한 곳부터 고른다: 사람이 아니라 AI가 결정한 부분, 결정 로그에 이유가 없는 부분, 마지막에 급히 바꾼 부분.

## 3. 한 문항씩 돈다

1. 질문 하나만 낸다. 힌트·정답을 함께 주지 않는다.
2. 사람이 코드를 보지 않고 실제 답안처럼 친다: **결론 1줄 → 근거 → 한계나 대안**, 3~5문장. "모르겠다"도 답이다.
3. 5줄 이내로 돌려준다: 맞은 것 / 틀리거나 빠진 것(근거 포함).
4. 구멍이 있으면 짧게 설명하고 **"자기 말로 다시"** 를 한 번 시킨 뒤 넘어간다. 한 문항을 붙잡고 늘어지지 않는다.

## 4. 끝내기

- 남은 시간 동안 구멍 난 문항을 표현을 바꿔 다시 묻는다. 이번엔 설명 없이 답부터.
- 사람이 그만하자고 하면 바로 끝낸다.
- 시간이 부족하면(세션에 쓸 시간 15분 미만) 의도·대안 비교·검증·한계 3문항만 한다.
- 마지막 말: 아직 약한 주제 3줄 이내, 그리고 **"제출을 확정하면 AI를 쓸 수 없습니다. 제출 점검으로 넘어가세요."**

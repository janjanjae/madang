# 탭 모드 라이트 (Codex)

마당의 탭 모드(팀장 1 + 팀원 N, 파일 신호로 조율)를 Codex 터미널 탭 2~3개로 줄인 판.
Claude판과 달리 **백그라운드 감시·커밋 게이트 훅이 없다** — 사람이 탭을 돌며 "브리프 확인해", "reply 확인해"를 직접 친다.

## 언제 나누나 / 안 나누나

- 나눈다: 서로 다른 파일을 건드리는 독립 슬라이스가 2개 이상 / 구현과 검증을 다른 눈으로 보고 싶을 때
- 안 나눈다: 작은 과제, 슬라이스가 같은 파일에 몰릴 때, 토큰 예산이 빠듯할 때 — **탭 1개 + 스킬이 기본**
- 나눠도 3개까지. 사람(팀장)이 따라잡을 수 있는 수가 상한이다.

## 역할

| 탭 | 역할 | 쓰는 것 |
|---|---|---|
| 1 구현 | plan.md의 슬라이스를 구현·커밋 | `$incremental-implementation` |
| 2 검증·리뷰 | 구현 탭의 커밋을 실행·테스트·엣지 케이스로 검증, FIX 사유 작성 | `$verification-before-completion`, `$debugging-and-error-recovery` |
| 3 조사 (선택) | 문서·라이브러리·데이터 확인, 결과를 메모로 | 읽기 전용 |

팀장은 사람이다 — plan.md를 쓰고, 브리프를 나누고, CONFIRM에 APPROVE/FIX를 내린다.

## 파일 신호 (최소)

```
.team/
  brief-<탭>.md        팀장 → 탭: 할 일, 인수 기준, 건드릴 파일, 금지 범위
  <탭>.request.md      탭 → 팀장: CONFIRM(검증 증거 첨부) / BLOCKED(막힌 이유) / DISCUSS(브리프와 충돌)
  <탭>.reply.md        팀장 → 탭: APPROVE / FIX(무엇을 왜)
```

- 탭 시작 프롬프트: "AGENTS.md와 `.team/brief-<탭>.md`를 읽고 시작해. 끝나면 `.team/<탭>.request.md`에 CONFIRM과 검증 출력을 남겨."
- CONFIRM에는 실행한 명령과 출력이 있어야 한다. 증거 없는 CONFIRM은 FIX.
- 같은 파일을 두 탭이 동시에 고치지 않게 브리프에 "건드릴 파일"을 적는다.
- `.team/`은 작업 기록이다 — 과정을 남기고 싶으면 커밋, 아니면 `.gitignore`.

## 흐름

```
팀장: plan.md → brief-구현.md
구현 탭: 슬라이스 구현 → 커밋 → 구현.request.md (CONFIRM + 실행 출력)
팀장: 검증 탭에 "구현 탭 마지막 커밋 검증해" → 검증 결과로 APPROVE / FIX
```

## 프로바이더 전환 방식 (이 환경 고유)

- 전환은 **셸 함수 = 세션(탭) 단위**: 탭에서 `use-glm` / `use-claude` 실행 후 `claude` 기동. `~/.zshrc`에 정의됨 (z.ai의 Anthropic 호환 엔드포인트로 `ANTHROPIC_BASE_URL` 교체 + haiku/sonnet/opus 티어를 GLM 모델로 매핑).
- GLM 모드의 티어 매핑: haiku→`glm-4.7`, sonnet→`glm-5.1[1m]`, opus→`glm-5.2[1m]` → GLM 모드 탭에서 `/model sonnet` = glm-5.1.
- **⚠️ 네이티브 팀 모드 제약**: 팀원은 리드의 env를 상속 → 팀 전체가 같은 프로바이더. **팀원별 프로바이더를 섞으려면 탭 모드 필수.**

### OpenCode 환경에서는 (Claude Code와 차이)

OpenCode에는 `use-glm`/`use-claude` 같은 셸 함수 전환 개념이 없다. 대신:

- **세션 중 전환**: `/models` 커맨드(키바인드 `ctrl+x m`)로 provider/model 피커를 열어 즉시 교체. 모델 ID 형식은 `provider/model-id` (예: `anthropic/claude-sonnet-5`, `opencode/claude-sonnet-5`(Zen 경유), `github-copilot/claude-opus-4-8`).
- **세션 시작 시 지정**: `opencode -m anthropic/claude-sonnet-5` 또는 `opencode --agent build -m ...`.
- **프로젝트/글로벌 고정**: `opencode.json`(프로젝트) 또는 `~/.config/opencode/opencode.json`(전역)의 `"model"`/`"small_model"` 필드, 또는 `agent.{이름}.model`로 팀원별 기본 모델을 아예 고정할 수도 있음.
- **프로바이더 인증**: `/connect`로 Anthropic(Claude Pro/Max), GitHub Copilot, ChatGPT Plus/Pro, OpenCode Zen 등 로그인. 여러 프로바이더를 **동시에** 연결해두고 세션마다 `/models`로 자유롭게 섞어 쓸 수 있음 — Claude Code처럼 "탭(세션) 단위로만 프로바이더를 고정"해야 하는 제약이 없다. 즉 네이티브 팀 모드 제약(팀원이 리드 env 상속)도 OpenCode에는 해당 없음 — 팀원마다 브리프에 다른 모델을 지정해도 세션별로 바로 반영 가능.
- **브리프 표기**: 위 "역할별 배분" 표의 모델명을 그대로 쓰되, `use-glm/use-claude` 대신 `provider/model-id`만 명시하면 된다 (예: "Sonnet 5 → `anthropic/claude-sonnet-5`로 세팅").

- 5시간 전에 쓴 토큰은 윈도우에서 자동 이탈 → 대형 스프린트는 몰아치기보다 분산이 같은 플랜에서 더 많은 사용량을 뽑는다.
- 주간 한도 **+50% 프로모션은 2026-08-19까지 재연장**됨 (2026-07-19 종료 예정이었으나 공식 X(@ClaudeDevs) 공지로 연장 — 웹서치 2026-07-19 확인). 종료 후에는 체감 주간 한도가 2/3로 줄어든 상태가 정상(버그 아님).
- "2배"는 별개 건: **5시간 한도가 2026-05-06부로 영구 2배** 확대된 것(프로모션 아님, 만료 없음). 주간 프로모션(+50%, 한시)과 혼동 주의.

### 모델 선택 영속성 (Claude Code 동작 특성)

- `/model` 선택은 `~/.claude/settings.json`의 `model` 키에 **저장되어 다음 세션의 기본값**이 된다 (마지막에 쓴 모델이 이어짐).
- 따라서 **Fable 5 / Opus 세션을 마칠 때는 `/model sonnet`으로 복귀**하고 끝내는 것을 습관화 — 안 그러면 다음에 무심코 연 세션이 최고 소비 티어로 돌아간다.
- 안전망: 세션 시작 시 **statusline의 모델 표기를 확인**하는 것을 기력회복 절차의 일부로 삼는다. Fable 5는 "세션별 명시적 opt-in 전용" — 전역 기본값이 되어 있으면 즉시 복귀.

## 역할별 배분 권장 (프로바이더 통합)

**기본 원칙(2026-07-13 갱신 — 이전 "전원 Sonnet 기본" 원칙 뒤집음)**: **팀장은 Opus 4.8 기본, 구현 워커는 Sonnet 5 기본.** 배경 변화 세 가지가 겹쳤다: ① 팀원이 코파일럿으로 상당 부분 이관되면서 클로드 쿼터에 여유가 생김(회사 업무는 코파일럿 우선 소진), ② 클로드 맥스 구독으로 쿼터 최대 활용이 목표가 됨, ③ 팀장 역할이 코드를 안 쓰는 **세션 1개**라 절대 소비량이 작다 — 반면 팀장의 판단(git diff 교차검증으로 미묘한 버그 잡기, 애매한 상황 판단, 스프린트 전체 장기 일관성)은 정확히 Opus 4.8이 Sonnet보다 앞서는 영역이라 레버리지가 크다("싼 보험"). 워커는 물량이 크므로 Sonnet 5 기본을 유지 — 공식 문서가 "코딩·에이전틱에서 near-Opus quality"라 명시할 만큼 격차가 좁아졌다.

**팀장을 Sonnet 5로 낮추는 경우**: 쿼터 부족·저위험 단순 배분·체크포인트 검토만 도는 짧은 세션. 기본값이 아니라 예외.

**워커를 Opus 4.8로 올리는 경우** (아래 중 하나, 선제적 판단이 어려우면 ②를 기본으로):
1. **되돌리기 비싼 설계 결정** — DB 스키마, 인증/보안, 상태머신 전면 재설계처럼 잘못되면 나중에 풀기 힘든 일회성 결정
2. **재시도 후 에스컬레이션** — Sonnet으로 브리프를 줬는데 결과가 명백히 부족하거나(재작업 필요) 막혔다는 보고가 왔을 때, 다음 시도부터 Opus로 격상. 처음부터 "어려워 보이니 Opus"로 선제 배정하지 않는다
3. **수 시간 단위 완전 자율 장기 작업** — 중간 체크포인트 없이 오래 도는 경우 Opus의 장기 일관성이 유의미
4. **파이리 에스컬레이션 디버깅**(2026-07-13 역할 개편) — 다른 팀원이 2회 이상 실패한 버그·통합/재현 불가/아키텍처급 버그는 배정과 동시에 Opus 4.8로

**Fable 5**: 팀장의 대형 설계·시스템 재설계 세션(예: 오늘 같은 에이전트 시스템 개편)에 한해 고려. 턴이 수 분씩 걸리고 가격이 Opus의 2배라 상시용 아님.

| **팀장(리드/오케스트레이터)** | **Opus 4.8** | 판단 밀도가 높은 저물량 세션 — 상위 모델 비용이 싸게 먹힌다. 대형 설계 세션은 Fable 5, 저위험 짧은 세션은 Sonnet 5로 낮춰도 됨 |

배분 시 팀장은 브리프에 `프로바이더 + /model 값`을 명시한다. 워커를 Opus로 격상할 때는 **왜 Sonnet으로 부족했는지 한 줄**을 브리프/보고에 남긴다(사후에 이 판단이 맞았는지 팀장이 성찰 루틴에서 검토할 수 있게).

### 프로바이더 거버넌스 — 감시 경계 (2026-07-23)

**코파일럿은 회사 계정이라 프롬프트가 회사 감시 대상일 수 있다.** 따라서 프로바이더 선택은 쿼터뿐 아니라 **어떤 내용을 어느 채널에 태우나**의 문제이기도 하다.

- **코파일럿(회사 계정) = 구현/생산 실행 프롬프트만.** 자기완결 브리프 기반의 "Task N 수행" — 코드·테스트·rebase 등 **정당한 회사 repo({app-repo}) 작업**. 회사 업무가 감시되는 채널에 남는 것은 정상이고 올바르다.
- **클로드(개인 계정) = 그 외 전부.** 팀장 오케스트레이션·전략/설계 논의·메타(팀 시스템 자체 개선)·개인 생산성(pokemon-agent-team·워라밸 자동화)·로토무도감 해설. 회사 감시 채널에 태우지 않는다.
- 이건 **우회가 아니라 데이터 거버넌스**: 회사 업무는 감시되는 코파일럿에 정확히 남기고, 개인·메타·전략은 개인 클로드에 둔다.
- **아키텍처적으로 기존 모델을 강화**: 팀장(클로드)이 "왜/무엇"을 자기완결 브리프로 압축 → 코파일럿 워커는 "실행"만 받는다. **사고·근거·전략은 클로드에 남고, 실행 지시만 코파일럿으로 건너간다.** 로토무도감을 클로드 탭에 두는 결정([[roster]])도 같은 선의 연장.

## 새 프로바이더 추가 절차 (확장 방안)

1. `~/.zshrc`에 `use-{이름}()` 함수 추가: `ANTHROPIC_AUTH_TOKEN` + `ANTHROPIC_BASE_URL`(Anthropic 호환 엔드포인트) + `ANTHROPIC_DEFAULT_{HAIKU,SONNET,OPUS}_MODEL` 티어 매핑 — 기존 use-glm 패턴 복사
2. 이 파일에 프로바이더 섹션 추가 (모델 표 + 비용 구조 + 관측 특성 + 티어 매핑)
3. "역할별 배분" 표에 해당 프로바이더의 적합 역할 반영
4. 팀 경험 축적 후 "관측된 특성"을 업데이트 (팀장 성찰 루틴에서)

## 🔴 이것만은 (잊으면 실제 사고가 났던 것들 — 경위는 incidents.md 같은 번호)

1. **브리프·reply는 한 번의 Write로 완성.** Write 후 Edit으로 덧붙이지 마라(워커 폴링은 첫 md5 변경 즉시 깬다) → 추가할 게 생기면 **전체를 다시 Write**하고 누락이 팀장 탓임을 명시.
2. **`NEXT:` 브리프는 `briefs/{인스턴스}.md`에도 쓴다. 순서는 `briefs/` 먼저, `reply` 나중.** 같은 시각에 쓰면 워커의 md5 기준선이 이미 새 내용이라 **변경이 영원히 감지되지 않는다.** 복구 = 브리프를 다시 Write(상단에 재신호 표시 + 팀장 실수 명시).
3. **감시 명령은 `while IFS= read -r f; do … done < <(find …)` 형태만.** `for f in "$C"/*.md`(매칭 0건이면 zsh fatal)·`for f in $(find …)`(zsh는 단어분리 안 함) 금지. 감지 결과는 변수로 받아 **루프 밖에서** 판단(안의 `exit`는 서브셸만 죽인다). **유휴 판정은 "보고가 현재 브리프보다 새로운가"부터** — 오래된 쪽이면 아직 기동 안 한 것이라 알릴 값이 없다. 완성본 `reference/confirm-protocol.md`.
4. **Jira 상태 전환은 사용자 소관.** 명시 요청 전 `transitionJiraIssue` 금지 → 티켓 생성·코멘트만 팀장이.
5. **`APPROVE`는 커밋 게이트다.** push·PR은 사용자 스모크 통과 후 **별도 지시**.
6. **워커가 "런타임 검증 못 했다"고 하면 팀장이 직접 확인하기 전엔 push 승인 금지.** 테스트 통과는 실환경 검증을 대체하지 못한다.
   - **6-B 최초 PR 순서**: ① 로컬 스모크(사용자) → ② **Draft** PR → ③ CI 후 Preview 스모크(사용자) → ④ Draft 해제 + 리뷰 요청 → ⑤ 승인 후 main 재머지 → ⑥ 머지. ②~③ 사이 push는 Draft라 허용. **이미 발행된 PR의 리뷰 반영분**은 push → CI → Preview 재확인만. 🔴 **발행 지시 전에 "최초 발행인가 리뷰 반영분인가"를 한 줄로 판정하라.**
   - **6-C 30분 이상 조사·구현이면 브리프에 "의미 있는 발견마다 reports에 append"를 명시.** 죽은 세션은 `/compact`도 못 한다.
7. **커밋·PR 본문 금지어**: 워커 이름(머지 커밋 포함) · `.claude/**` 경로 · `Co-Authored-By`. 팀 운영 구조가 회사 PR에 노출된다.
8. **팀장은 소스 파일을 직접 수정하지 않는다.** 가능 영역: `.claude/TASKS.md`·`.claude/PROGRESS.md`·`.claude/team/**`·이 스킬의 supporting 파일.
9. 🔴 **마이그레이션이 있는 브랜치는 rebase·push 전에 타임스탬프를 대조한다. 기준은 반드시 merge-base** (`origin/main..HEAD` 금지 — 양방향 diff라 오판):
   ```bash
   MB=$(git merge-base origin/main HEAD); git diff --name-only $MB..HEAD -- .../migrations/   # 이 브랜치가 분기 후 추가한 것
   git ls-tree --name-only origin/main .../migrations/ | sort | tail -1                       # 앞의 것들이 전부 이보다 커야 한다
   ```
   rebase를 지시할 때 이 확인을 함께 지시. **`DB Migration Guard`를 믿지 마라**(낡은 base로 돈다) → 머지 제안 시 `git merge-base --is-ancestor origin/main {브랜치}`가 false면 **"Update branch 누르세요"** 안내 + 재대조. 적용된 마이그레이션 파일명 변경 금지(재실행됨) → `up`/`down` 멱등성 확인. 상세는 `db-migration-order-check` 스킬 — **팀장 사전 대조 → 워커 수정** 순서.
10. 🔴 **사용자와의 대화 턴을 시작할 때마다 `confirm/*.request.md`부터 확인한다.** 감시 루프는 보조 수단(세션 교체·압축·몰입으로 끊긴다). 워커 유휴는 토큰이 아니라 팀장이 만든다.
    ```bash
    find .claude/team/confirm -name "*.request.md" | while read -r x; do [ ! -f "${x%.request.md}.reply.md" ] && echo "🔴 미처리: $x"; done
    ```
11. 🔴 **머지·cherry-pick 리허설은 `typecheck`까지 돌려야 끝난다.** "충돌 0"은 텍스트 결과일 뿐 동작 보장이 아니다.
    ```bash
    TMP=$(mktemp -d); git worktree add --detach "$TMP/r" {대상브랜치} --quiet; cd "$TMP/r" && git cherry-pick --no-commit {커밋} && pnpm nx typecheck api && pnpm nx typecheck web
    ```
12. 🔴 **reply를 쓰기 직전에 request를 다시 읽어라(`cat request`).** 워커는 request에 진행분을 이어 붙인다 — **읽는 쪽이 맞춰야 한다.** mtime 감시(`request -nt reply`)로는 못 잡는다(reply가 최신인 게 맞고 내용만 낡은 경우). 교차검증이 길었던 사이클일수록 그렇다.
13. 🔴 **워커의 결론을 사용자에게 올리기 전에, 그 결론이 딛고 선 조건식·상수·저장값을 코드로 열어라.** 워커 문서 안의 앞뒤 모순은 팀장이 잡을 자리(워커는 통과시키려 하고 팀장은 통과시킬지 정한다). **한 층에서 확인한 사실을 다른 층으로 외삽하지 마라** — 코드→화면, 디스크→화면, main→CI, 환경→데이터: 화살표마다 확인이 새로 필요하다.
14. **브리프·reply는 절대경로로 쓰고 쓴 뒤 `md5`로 존재를 확인한다.** 팀장 셸의 cwd는 조사 중에 옮겨간다 — 상대경로 heredoc은 조용히 실패한다.
15. 🔴 **브리프를 내기 전에 최근 회의 결론과 대조한다.** 팀장은 티켓·PR을 과하게 끊는 경향이 있다 → 쪼개고 싶을 때마다 **"최근 회의에서 정한 방향과 맞나"**를 먼저 본다. 🔑 **근거가 무너지면 그 위에 세운 결론도 같이 재검토한다.**
16. 🔴 **"일부 테스트 실패는 정상"을 전제한 브리프는 `pre-push` 훅과 충돌한다**(훅은 실패의 성격을 구분하지 않는다) → 브리프에 ①"이 실패는 예상되므로 `--no-verify` 승인"(사유 포함) 또는 ②"push 전 main을 병합해 해소"(병합 금지와 모순되지 않게) 중 하나를 명시. 🔑 근본적으로 **실패가 정상인 상태로 push하는 태스크를 만들지 마라** — 순서를 바꿔 실패 없는 상태를 먼저 찾는다.
17. 🔴 **사용자가 화면에서 겪은 것을 워커의 코드 판정으로 덮지 마라.** 코드에 가드가 보여도 사용자가 실제로 겪었다면 **"막지 못하는 경로"가 있다는 뜻**이다 → 워커 판정이 "이미 해결됨"으로 오면, **사용자 실측과 충돌하는지 먼저 확인**하고 충돌하면 그 판정을 반려한다. 티켓 제목·본문을 **통째로 교체하지 마라** — 원 의도를 남기고 새로 찾은 것은 **별개 티켓으로 분리**한다.
    - 실사고(2026-09-01, PROJ-1183): 사용자가 「SA 검토결과서 편집 화면 버튼」을 올렸는데 워커가 다른 화면(`ArbReviewActions`)을 지목했고, 팀장이 그걸 받아 **제목·본문을 전면 교체**해 원 이슈를 지웠다. 사용자가 잡아 복구 + 동시성 건은 별도 티켓 분리. 재확인 결과 **편집 화면에 실제로 `disabled` 없는 버튼 2개**가 있었다 — 워커가 1·2차 모두 놓친 것이다.

18. 🔴 **기존 코드·주석·문자열을 근거로 삼기 전에, 그것이 런타임에 실제로 무엇을 가리키는지 열어라.** 13이 *워커의 결론*을 다룬다면 이건 **레포에 이미 있는 산출물**이다 — 살아 있는 코드라는 사실이 그 서술이 지금도 참이라는 뜻은 아니다. 특히 ①다른 기능의 기존 구현을 "선례"로 이식할 때 ②주석이 밝힌 *이유*를 그대로 옮길 때 ③프롬프트·라벨 문자열을 사양으로 인용할 때 ④로그 한 줄을 화면 동작으로 서술할 때.
    - 🔑 **판별 질문 하나**: *"이 서술이 가리키는 대상을, 내가 이 세션에서 직접 열어봤는가?"* 아니면 근거로 쓰지 마라.
    - 실사고(2026-09-02, 하루에 5건 — 전부 사용자가 잡았다):
      ① **Vera 재검토 구현을 956 브리프에 청사진처럼 실을 뻔했다.** Vera 기준선은 *발견사항(Fail) 목록*이라 Pass 개념이 없는데 셀프체크는 *9항목 고정 표*다 — 그대로 옮겼으면 표가 안 채워진다. 사용자가 *"조금은 다를 수도 있어 참고만"* 으로 잡았다.
      ② **FE 주석의 근거를 검증 없이 복사했다.** *"'권고'/'N/A'는 `ARB_RESULT_VERDICT_LABELS`에 없으므로 원값"* 은 **타입 구조상의 사고**지 디자인 결정이 아닌데, 그걸 Confluence 쪽 지시 근거로 썼다.
      ③ **`head -15`로 잘린 출력에서 "Slack 알림은 데드코드"로 갈 뻔했다.** 15줄이 module 등록·spec으로 다 차서 진짜 호출부가 잘렸다. (같은 규칙이 「팀원 작업 규율」에도 있는데 팀장이 어겼다.)

## 운영 모델 (역할분담·상태관리, 2026-07-14 확정)

- **역할**: 사용자 = 스모크(팀장이 항목 제공 → 직접 확인+피드백) + 버그/개선 아이디어. 팀장 = ①버그/아이디어를 Jira 적정 위치에 적재 ②워커 상태·보고 → 다음 브리프 배분 ③area 스트림 단위 + 모든 스모크 완료 시 PR 제안 → 사용자 컨펌 → PR.
- 🔴 **모든 PR은 발행 전에 로컬 스모크 + 사용자 직접 피드백을 거친다.** "Preview에서 밟자"로 대체하지 마라(Preview는 리뷰어용) → 로컬 서버가 1세트뿐이면 포트 오프셋 +1로 워크트리 2개 동시 기동(`_local-runtime.md` "병렬 스택"). 스모크 순번을 이유로 PR을 먼저 올리자는 제안은 원칙 위반.
- 🔴 **Jira 상태 전환은 사용자가 한다**(그 과정 자체가 사용자의 현황 파악 수단). 티켓 **생성**(`/issue-capture`)·**코멘트**는 팀장.
- **상태 관리 = Jira 중심 하이브리드**: Jira = 티켓별 상태 SSOT(상태전환 사용자 / 마일스톤 코멘트(배분·커밋·스모크통과·PR)는 팀장, **진행 중 계속 갱신**) · TASKS.md = 얇은 오케스트레이션(PR 로드맵·스트림·현재 배분) · PROGRESS.md = 세션 체크포인트.
- 🔴 **팀장의 Jira 관할 = `assignee = currentUser()`인 이슈뿐.** 백로그 JQL에 이 조건을 **항상** 붙인다 → `project = X AND status != 완료` 류 전체 스캔 금지. **미할당(`assignee IS EMPTY`)을 "내 것"으로 단정하지 마라** — 남의 이슈에 우선순위를 매기면 오보·오배치·중복 작업. 예외: `/issue-capture`로 직접 만든 티켓.
- 🔴 **`duedate` = 그 티켓이 나갈 PR 묶음 식별자.** 생성 시엔 비운다 → **배분(브리프 작성) 시점에 `duedate` + 시작일(`customfield_10015`)을 반드시 채운다.** 그러면 `assignee = currentUser() AND duedate IS EMPTY AND status != 완료` 한 줄이 미배분 백로그(킥오프·성찰에서 그것만 훑는다). 묶음의 정확한 SSOT는 PR 링크 코멘트 — 라벨 등으로 Jira에 더 인코딩하지 마라.
- **토큰 절제**: Jira 읽기 최소화(`fields` 파라미터 + 재조회 금지), 쓰기(짧은 코멘트)는 자유.

  - **절단된 출력(`head`·`tail`·페이징)으로 결론 내지 마라** → "없다"를 말하려면 절단 없이 다시 돌려라. (2026-09-01: 파이리가 `head` 절단 때문에 "패널이 어디에도 마운트 안 됨"으로 잘못 봤다가 재확인해 정정 — **스스로 정정하고 그 경위를 보고한 것이 옳은 처리**다)
  - 스크립트로 파일을 편집할 때 `str.replace` 결과를 믿지 마라(들여쓰기 차이로 no-op) → **`assert old in s` 필수**. 팀장의 python 편집도 동일.

## 워크트리 표준 (2026-07-28 — 공유 트리 폐기)

- **기본값 = 워커별 워크트리 격리.** 병렬성은 "워커별 독립 브랜치"에서 나온다. 메인 트리(`/{repo}`)는 `main` 고정 — 워커 코드 작업 금지, 팀장이 git 교차검증(읽기)만. 각 PR/워커 = `.claude/worktrees/wt-{ticket}` + `fix|feat/PROJ-xxx`(origin/main 기준 분기). approve = feature 브랜치 커밋 → push → PR → main 머지(ruleset 보호).
- ⚠️ **워크트리 생성 직후 셋업 필수**(gitignored env·`.claude/team`이 안 딸려온다): `reference/worktree-setup.md`. 브리프에 "wt-{ticket} 생성 + 그 체크리스트"를 명시.

## 보고 양식 (필수)

`[커밋 SHA] + 한일 3줄 + 다음 의존성 풀림/막힘`. 미준수는 재요구. 막힘(blocked)은 원인 + 시도한 것 + 필요한 결정.

## 컨펌 신호 프로토콜 (요약 — 완성본 `reference/confirm-protocol.md`)

- 신호 디렉토리 `{프로젝트}/.claude/team/confirm/`: `{인스턴스}.request.md`(**팀원** — `CONFIRM`/`BLOCKED`/`DISCUSS` + 한일 요약 + 간략 테스트 플랜 + 변경 파일) / `{인스턴스}.reply.md`(**팀장** — 첫 줄 `APPROVE` 또는 `FIX`, `---` 뒤 `NEXT:` 브리프 가능 — 🔴 그때는 `briefs/`에도). 사이클 종료 시 팀원이 두 파일 모두 삭제. 잔여 파일 = 미처리 신호.
- 팀장 감시는 배분 완료 후 **`Monitor(persistent: true)`**(명령 전문·오탐 노트는 confirm-protocol). request 감지 → **git diff 교차검증** → 사용자에게 한일 요약+테스트 플랜 → 판단 → reply → 감시 재무장. 감시는 **보조 수단** — 매 턴 `confirm/` 직접 확인(「이것만은」 10). `BLOCKED` = 의사결정 요청, `DISCUSS` = 근거 대 근거 판단. 타임아웃 백오프 1h→2h→4h.
- 코파일럿/클로드 무관하게 경로 동일 — 사람 릴레이 불필요. 수동 채팅 컨펌은 fallback.

## 검증·체크포인트

- 팀장은 보고를 **git으로 교차검증**(`git show --stat`, grep) 후 TASKS 갱신. **검증 1차는 워커 자기-스모크**(팀장은 코드를 못 고쳐 왕복이 유휴를 만든다) — 워커가 [돌려보기 → 고치기 → 재확인]을 컨펌 요청 **전에** 끝내고 증거 첨부. 체크포인트 검증(테스트 전체/빌드/E2E)은 팀원 명령·팀장 확인. 📌 **유닛테스트·CI가 green이어도 실 LLM·실환경을 돌려야 나오는 결함이 있다** → LLM 워크플로우·외부 연동 변경은 **실행 검증을 별도 태스크로 배분**하고 사용자 직접 확인 항목으로 분리.
- **스모크 핸드오프 4종 세트** — 사용자가 "스모크하겠다"/"시나리오 줘"라고 하면 팀장이 **항상 한 번에** 제공:
  1. **서버 기동** — 검증 대상 코드가 있는 트리에서(커밋 전 변경이면 그 워크트리, 머지 후면 메인 트리). 인프라 컨테이너 확인 → 대상 트리 `env.local` 전 앱분 → stale 서버 종료 → **전 앱 기동**(목록은 `_local-runtime.md`가 SSOT — 앱 하나를 빠뜨리면 에러 없이 스모크가 통째로 무효) `run_in_background: true` → 리스닝·로그 확인 → **기동 시각 명시**(dev api는 HMR 없음). 🔴 **기동 전 "지금 그 포트를 잡은 게 어느 워크트리인가"부터 확인**(`lsof -a -p {pid} -d cwd`) — 남의 것이면 **포트가 아니라 워크트리 경로로 찾아** 그것만 kill. Redis 등 공유 백킹서비스는 `REDIS_PREFIX=local:{ticket}`로 분리. 앱이 분리되는 PR이 머지되면 그날 `_local-runtime.md` 갱신.
  2. **로그 tail 명령** 동봉(백/프론트 output 파일 경로).
  3. **체크 시나리오** — `[사용자]` 항목 + 워커 `[기계]` 증거 요약만. 워커 증거가 없으면 핸드오프 전에 워커에게 먼저 돌려보낸다. 팀장이 DB/git으로 확인할 항목은 구분.
  4. **⭐ 바로 쓸 수 있는 기존 데이터** — 시나리오를 밟을 실제 프로젝트·케이스를 DB에서 찾아 프로젝트명 + URL(또는 project_id) + 근거까지. **사용자가 매번 새 프로젝트를 만들게 하지 마라.** 없으면 "없음 + 신규 생성 필요".

## 세션 수명주기

- **워커(탭 모드)**: `/pairi`·`/metamong` 등으로 정체성 로드 + 기력회복(보고 파일 → TASKS/PROGRESS → git 교차확인) 후 브리프 대기. **세션 유지가 기본**(같은 도메인 연속 태스크는 컨텍스트가 자산). 리셋 기준 = ①도메인 전환(BE↔FE) ②컨텍스트 압박(잔량 ~20% 이하·품질 저하 체감 — 대형 태스크 **시작 전에** 선제) ③M+ 태스크 착수 직전. **세션은 소모품, 상태는 파일에**(정체성 `agents/{name}.md`·이력 `reports/`·TASKS/PROGRESS·git) — 보고 파일 기록 생략 금지. 세션 사망은 상시 리스크 → 복구 키워드 **"이어서"**(워커가 ①브리프 ②reply 순으로 읽고 재개). 복구 브리프: ①"이전 태스크는 끝났다" ②팀장이 git으로 확인한 진행도 표 ③"밖에서 본 것이니 `git diff`로 직접 확인하고 시작" ④끊기기 직전의 좋은 접근을 명시적으로 살려준다.
- **팀장 세션**: **기본은 compact로 이어간다**(라이브 연결·감시 재무장 비용이 새 탭보다 크다). 🔴 **compact 직전에 `/save-progress`** — 상태가 파일에 없으면 compact도 새 탭도 위험. 새 탭이 나은 시점: ①국면 전환(워커도 유휴) ②하루 시작 ③사용자가 판단 품질 저하를 느낄 때. **`/compact`는 남길 것을 지시해서**: `/compact 현재 배분 상태(워커별 브리프·컨펌 대기)·오늘 내린 결정과 이유·미해결 FIX·다음 배분 후보만 남겨. 조사 과정과 중간 시도는 버려도 됨`. 시점은 **작업 사이 휴지기**와 **1시간 이상 자리를 비우기 직전**(캐시 만료 — 쉬고 돌아온 첫 턴은 어차피 전체 재계산, 그때 compact가 가장 비싸다). 자동 컴팩션 창은 **기본값(모델 한도)을 유지**한다 — 200k 자동 접기는 작업 중간에 맥락을 잃고 대기·캐시 재구축 비용이 매번 붙는다(08-31 시도 후 같은 날 철회). 주 1회 `/usage`에서 **Long context 플래그 ≥10%**가 뜨면 그때 `/autocompact 500k`를 검토한다. 컴팩션 뒤 supporting 파일은 **필요 절만 재독**(전체 재독 금지) — 「이것만은」은 `SessionStart(compact)` 훅이 자동 재주입한다(2026-08-31). **모델·effort는 세션 시작 때 정하고 중간에 바꾸지 않는다**(`/model`·`/effort`·fast·MCP 연결/해제·compact는 캐시 접두사를 깬다 / `/rewind`·Skill 호출·서브에이전트 스폰은 지킨다). 돌고 있는 워커에게 모델 변경 지시 금지. **불변 규칙은 `memory/`에**(매 세션·매 compaction 재주입, supporting 파일은 아님).

## 스킬·모델·사용량

- 역할·시점별 스킬 매핑은 `skill-guide.md`. 허브 문서 쓰는 스킬(`/kickoff` `/save-progress`)은 팀장 전용, 워킹트리 건드리는 자동 수정(`/simplify`, `/code-review --fix`)은 팀원 세션 금지(정리 태스크로 발행). **스킬 인벤토리 점검** = 월 1회/스프린트 종료 성찰 `/skill-audit`(신설·이동·폐기 시 즉시). SSOT는 파일 시스템.
- **모델: 티어는 직급이 아니라 자율성에 붙는다.** 팀장(대화형, 짧은 턴) = Opus / 구현 워커 = 판단 있으면 Opus, 순수 기계 물량은 Sonnet(또는 Opus `medium`) / 장시간 자율 디버깅·대형 설계 단독 세션 = Fable. 팀장을 Fable로 상시 격상하지 않는다. 판별 신호·effort 축·비용 우선순위는 `model-guide.md` — Opus 배분엔 **해당 신호 한 줄**. 기동은 `GO_MODEL={tier} go-{worker}`(기본 워커 sonnet/팀장 opus) — **모델은 브리프보다 먼저**. `/model`은 에이전트가 못 친다 → 사용자가 그 탭에서. 🔴 **Fable/Opus 태스크 종료 시 `/model sonnet` 복귀 안내**(선택이 다음 세션 기본값으로 영속). 전역 기본은 opus(2026-08-31 정정). `advisor` 같은 옵션은 없다. 프로바이더 혼용은 탭 모드에서만.
- **사용량 게이트(맥스 플랜)**: statusline 80%(빨강) = Opus/Fable급 신규 착수 금지 → Sonnet 물량 우선, 팀장 판단·대형 설계는 5시간 리셋 후. 50%(노랑)부터 잔량 의식. 주 후반 대형 배분 전 `/usage`로 주간 게이지(임박 시 워커 물량을 코파일럿으로). 🔴 **주 1회 `/usage`·`/insights` — 시점은 「금요일 퇴근 전」으로 고정**(2026-09-01 신설). 요일이 다르면 주간 누적치가 달라 **비교가 성립하지 않는다** — 금요일 퇴근 전이 그 주 작업이 다 반영된 시점이다.

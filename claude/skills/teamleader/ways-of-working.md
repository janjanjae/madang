# 팀 일하는 방식 (Ways of Working)

> 팀장이 관리·성찰·업데이트하는 팀 운영 규칙. 변경 시 하단 이력에 기록.

## 운영 모델 (역할분담·상태관리, 2026-07-14 확정)

- **역할**: 사용자 = 스모크 테스트(팀장이 테스트 항목 제공→직접 확인+피드백) + 버그/개선 아이디어 제공. 팀장 = ①버그/아이디어를 Jira 적정 위치 적재 ②워커 상태·보고 파악→다음 브리프 파일 배분 ③적정 단위(area 스트림)+모든 스모크 완료 시 PR 제안→사용자 컨펌→PR.
- **상태 관리 = Jira 중심 하이브리드**: **Jira = 티켓별 상태 SSOT(사용자 현황판)** — 상태전환(배분→`진행 중` / 머지→`완료`) + 마일스톤 코멘트(배분·커밋·스모크통과·PR). **TASKS.md = 얇은 오케스트레이션**(PR 로드맵·스트림·현재 배분). **PROGRESS.md = 세션 체크포인트**. ⚠️ 구 "Jira는 PR 후에만" 규칙 폐기 — 진행 중 계속 갱신.
- **토큰 절제**: Jira 읽기 최소화(`fields` 파라미터 + 재조회 금지), 쓰기(전환/짧은 코멘트)는 자유.

## 문서 규율

- **단일 작성자**: `.claude/TASKS.md`·`.claude/PROGRESS.md`는 팀장만 수정. 팀원은 읽기 전용.
- **팀원 보고 파일**: `.claude/team/reports/{이름}.md` — 각 팀원이 **자기 이름 파일만** 수정 (최신 보고를 맨 위에 추가). 팀장이 읽고 허브 문서에 반영.
- TASKS 갱신은 해당 라인만 Edit (전체 재작성 금지). PROGRESS는 체크포인트/세션 종료 시.

## 태스크·브리프

- **프로젝트 특화 애든덤 (2026-07-26 신설)**: 프로젝트 **상시** 특화(컨벤션·기본 발동 스킬·재기동 절차 등)는 브리프가 아니라 `{프로젝트}/.claude/team/agents/{이름}.md` 애든덤에 둔다 — 팀원 기력회복 시 베이스 정의 위에 겹쳐 적용(충돌 시 애든덤 우선). 팀장이 프로젝트 시작/중간점검 때 작성·현행화한다(팀장 수정 가능 영역 `.claude/team/**` 소속, gitignore라 회사 동료 비노출). 통째 복사 오버라이드 금지 — 베이스 업데이트가 자동 반영되게 애든덤은 델타만. 브리프는 '이번 태스크' 계층으로 한정.
- 브리프는 **자기완결**: "PROGRESS.md+TASKS.md 읽고 Task N만 하고 멈춰" 형식 + 범위·AC·검증 방법·권장 모델(프로바이더 포함) 명시.
- **재사용 후보 명시 (2026-08-12 신설)**: 팀장은 배분 전 관련 기존 모듈·헬퍼·공용 컴포넌트를 한 번 스캔(grep/Glob)해 브리프에 `재사용 후보: {경로 — 한 줄 근거}` 줄로 명시한다. 재사용할 게 없으면 `재사용 후보: 없음 — {신규 구현 사유 한 줄}`. 워커의 최소코드 사다리(agents/*.md 작업 규율)가 이 줄을 출발점으로 삼는다 — "결정의 순간에 큰 그림·기존 모듈을 떠올리는" 책임의 절반은 배분자인 팀장에게 있다.
- **브리프 전달 = 파일 기반 자동 수령**(2026-07-14 개정, 코파일럿도 파일 읽음 확인 → 수동 붙여넣기 폐기): 팀장은 브리프를 `.claude/team/briefs/{instance}.md`에 write. 워커는 세션 **시작 프롬프트 1회**(인스턴스명 지정 + `/metamong`·`/pairi` 기력회복 + 자기 브리프 파일 폴링 지시)만 사람이 붙여넣고, 이후 브리프는 워커가 파일 폴링(md5 비교, 15초)으로 자동 수령·실행. 태스크 완료(커밋+보고+컨펌사이클) 후 다시 폴링해 다음 브리프 대기. → **사람 개입은 탭당 시작 프롬프트 1회뿐**. reply.md 폴링과 동일 패턴(팀장이 파일 write = 워커 세션 깨어남).
  - ⚠️ **폴링은 반드시 `run_in_background: true`로 fire-and-forget** — harness가 백그라운드로 관리하고 **exit(파일 변경) 시에만 세션을 재호출**한다. sleep 도는 동안 LLM 무관 = 토큰 0. **포그라운드 read 루프(180초 타임아웃마다 LLM이 "출력 왔나" 재확인) 금지** — 그러면 매 사이클 토큰을 태운다. 팀장 감시(`run_in_background`)와 100% 동일 메커니즘. (2026-07-14 실측: 시작 프롬프트에 이걸 명시 안 했더니 워커가 포그라운드 read 루프로 돌려 ~3분마다 LLM 재engage하며 토큰 낭비 → 명시 필수.)
  - 시작 프롬프트 템플릿: `너는 {메타몽}이다(인스턴스: {metamong}). /metamong 기력회복 후: ① .claude/team/briefs/{metamong}.md 읽고 그 브리프만 수행 ② 완료 후, 브리프 파일 md5가 바뀌면 exit하는 폴 루프를 반드시 run_in_background(백그라운드)로 실행 — 절대 포그라운드로 read하며 기다리지 말 것. harness가 파일 변경 시에만 너를 깨운다. 깨어나면 브리프 다시 읽고 수행. 반복.`
- **인스턴스 네이밍 규칙**(2026-07-29 확정): **첫 인스턴스 = 무번호**(`metamong`·`pairi`·`kkobugi`·`rotomdex`) = 논리적 1번. **병렬 2번째부터만 숫자**(`metamong2`, `metamong3`…). **`metamong1`은 만들지 않는다.** 근거: 2번째가 붙어도 **이미 돌던 첫 워커의 파일(폴링 경로 briefs/reports/confirm)을 리네임할 필요가 없다** — 무번호 워커는 그대로 두고 `{이름}2`만 추가한다(대칭 번호였다면 매번 1번을 리네임해 폴링이 끊김). 단일 인스턴스가 다수인 공통 케이스를 깨끗하게 유지.
- **병렬 다중 세션**(2026-07-09): 파이리/메타몽/꼬부기는 각각 동시에 여러 세션 운영 가능 — 첫 인스턴스는 무번호, 2번째부터 숫자로 구분(`metamong` + `metamong2` + `metamong3`…). 병렬 가능한 작업이 있으면 브리프를 인스턴스별로 따로 써서 동시에 배분해 속도를 높인다. 보고 파일도 `{이름}.md`/`{이름}2.md`로 분리(파일 경합 방지).
- 병렬 배분 시 팀원 간 **파일 경로가 겹치지 않게** 분할 (예: 백엔드/프론트, 또는 동일 역할 인스턴스 간 도메인 분할). 겹치면 직렬로.
- 의존성 있는 태스크는 선행 커밋 SHA를 브리프에 명시.
- **AC에 실제 값 명시**: 문자열·타입·파일경로·API 응답 shape 등 "통과/실패를 판단할 수 있는 구체적 값" 포함. "X를 구현"이 아니라 "X=`'검토 요청됨'`" 수준으로.
- **UX 통합 설계 선행**: 팝업·페이지 단위 구현이 2개 이상 태스크로 분산될 때, 배분 전 "상태×컴포넌트 매트릭스" 또는 텍스트 레이아웃을 팀장이 먼저 정의. 꼬부기 있으면 꼬부기에게 위임.
- **꼬부기 브리프는 의도 중심으로**(2026-07-09): 꼬부기에게 줄 때는 세부 UI를 팀장이 미리 확정하지 않아도 됨 — 개선 의도/문제 상황만 전달하면 꼬부기가 기존 화면과의 조화 여부를 스스로 판단하고 디자인 관점(색상·레이아웃·톤)까지 포함해 방향성을 구체화한다.
- **Jira 스토리 ↔ PR 1:1 + 스토리 ↔ TASKS.md 태스크 묶음 매핑**(2026-07-12 개정): 스토리 1개 = PR 1개 = 브랜치 1개 = 에이전트 1명. 크기 상한(변경 400줄 또는 브랜치 2일) 초과가 예상되면 **서브태스크 분해가 아니라 스토리 분할**(`/issue-refine` 착수 전 모드 — 수직 우선, 기술 분할은 에픽·이슈 링크로 묶어 허용). 서브태스크는 PR·브랜치·기록 단위에서 제외(스토리 내 체크리스트로만). 스토리의 태스크가 TASKS.md Phase에 매핑 안 되면 명시적으로 새 Phase 추가 — "신규(변경 #N)" 메모만 남기고 태스크 목록에서 빠지면 미구현으로 이어짐. 상세 근거: `~/Desktop/agent-system-upgrade/reports/03-git-rules.md` · `03-jira-rules.md`.
- **Jira 읽기는 캐시로**(2026-07-12): 스토리 착수 시 팀장이 `/issue-cache`로 `.claude/stories/{키}.md` 생성 → 팀원은 Jira 직접 조회 금지, 캐시만 참조. Jira 쓰기는 PR 머지 시 `/issue-refine` 완료 후 모드 1회.

## 워커 기술 주체성 (2026-07-22 도입)

팀원은 "시킨 대로 다 하는" 실행기가 아니라 기술 전문가다. 브리프 = "무엇을·왜"의 계약, "어떻게"는 팀원의 전문 영역.

- **착수 전 기술 검증**: 관련 공식문서·베스트프랙티스를 먼저 확인(`source-driven-development`)해 브리프의 접근이 기술적으로 합리적인지 스스로 검증한 뒤 진행.
- **비충돌 세부 판단은 자율**: 브리프와 충돌하지 않는 구현 세부(패턴·API 사용법·에러 처리)는 팀원이 결정하고 근거(공식문서 링크)를 보고에 한 줄로 남긴다.
- **충돌하면 DISCUSS**: 브리프 지시 자체가 불합리하다고 판단되면 임의로 벗어나지 말고 `DISCUSS` request로 근거+대안을 제시해 팀장과 논의(아래 컨펌 프로토콜). 팀장은 DISCUSS를 반려 사유가 아니라 **품질 신호로 환영**한다 — 근거가 타당하면 브리프를 수정한다.
- **비례 원칙**: 한 줄 수정에 문서 조사를 붙이지 않는다. 설계 선택이 갈리는 지점에만.
- 팀장 측 대응: 브리프에 "왜"를 반드시 포함(팀원이 검증할 기준점), DISCUSS reply는 근거 대 근거로 판단하고 결정 이유를 남긴다.

## 팀원 작업 규율

- **DB 마이그레이션 파일 생성 시 `db-migration-order-check` 스킬 사용 필수** — `apps/api/migrations/`는 여러 팀원·워크트리(파이리/메타몽/꼬부기)가 동시에 파일을 추가해 타임스탬프 충돌이 반복됨(2026-07-08~09 사이 `제발`/`8c8391ed`/`b72ceb18` 등 3회 이상 재발). pull 직후·PR 전·merge 직전 3단계에서 스킬의 체크포인트 절차를 따를 것. **이미 적용된 마이그레이션은 절대 리네임 금지**(다른 환경 `pgmigrations` 추적 깨짐 — `b72ceb18`가 실제 사고 사례).
- **자기 파일 경로만 `git add`. `git add -A` 금지.** (워크트리 격리가 기본이라도 습관 유지 — 아래 "워크트리 표준" 참조)
- 커밋 전 테스트/빌드/린트 필수. 실패 상태로 커밋 금지.
- **커밋 전 테스트+컨펌 필수**(2026-07-09 도입, 2026-07-12 경로 개정): 자동 검증(테스트/빌드/린트) 통과만으로 임의 커밋 금지 — **간략한 테스트 플랜(핵심 항목 몇 개만)을 담은 컨펌 요청을 아래 "컨펌 신호 프로토콜"로 팀장에게 보내고 APPROVE를 받은 뒤에만** 커밋(전 팀원 공통, 페르소나 파일 `~/.claude/agents/{pairi,metamong,kkobugi}.md`에도 반영됨). 사용자 테스트는 팀장 세션에서 이루어지고 그 결과가 reply에 반영된다. 장황한 전체 케이스 나열 금지 — 이번 변경에서 반드시 확인해야 할 것만. 브리프에 **"컨펌 생략"**이 명시된 태스크(순수 리팩터·테스트 코드·문서 등 런타임 확인 불필요)만 자동 검증 통과로 바로 커밋 가능.
- **백엔드 수정 시 서버 재시작은 팀원이 알아서**(2026-07-09): `apps/api` 코드를 고쳐 테스트해야 하면 `lsof -nP -iTCP:8080 -sTCP:LISTEN`으로 PID 찾아 kill 후 `pnpm nx serve api > /tmp/api-dev-server.log 2>&1 &`로 재기동 — 사용자에게 묻지 않고 직접 수행(페르소나 파일에 반영됨).
- **기존 프로젝트로 테스트 불가한 변경은 명시**(2026-07-09): 신규 생성 시점에만 적용되는 로직이라 기존 프로젝트/케이스로 확인 안 되면, 테스트 플랜에 그 제약을 명확히 적도록 팀원에게 요구.
- **커밋 메시지: 한글, Conventional Commits + Jira 티켓 번호. Co-Authored-By 절대 금지. PR body에 Claude Code 태그 금지.**
- **PR 본문 `## Test Plan` = "Preview 환경에서 리뷰어가 밟을 액션 → 기대 결과" 전용 (2026-08-05 브리프 반영 의무화).** 팀장은 **브리프에 이 목적과 배제 기준을 반드시 실어라** — "체크리스트 필수"만 쓰면 워커가 자동검증 결과를 채워 넣는다. **제외 대상**: ①`nx test`/`lint`/`build` 등 **CI가 하는 검증** ②**로컬 전용 데이터**(특정 프로젝트 UUID 등 — preview에 없어 리뷰어가 밟을 수 없다) ③API 응답·DB 직접 조회 같은 **UI 액션이 아닌 것**. 체크박스는 **빈 채로** 두고 리뷰어가 채운다. 상세: 개인 메모리 `feedback_pr_title_format`(2026-07-30 재정의).
- ⚠️ **PR 본문·커밋 메시지에 `.claude/**` 내부 경로를 절대 쓰지 마라 (2026-08-05 명문화).** `.claude/team/**`(proto-shots·briefs·confirm·reports·plans)은 **gitignore 영역**이라 ①리뷰어가 열 수 없는 죽은 링크가 되고 ②우리 팀 운영 구조(워커 이름·브리프 체계)가 회사 PR에 노출된다. 스크린샷은 **GitHub에 직접 첨부**하거나, 첨부가 어려우면 **"어떤 시나리오를 육안 검증했는지" 텍스트로만** 적는다. ## 워크트리 표준 (2026-07-28 신설 — 공유 트리 폐기)

**기본값 = 워커별 워크트리 격리.** 공유 메인 워킹트리에서 여러 워커가 직접 작업하던 방식은 폐기(브랜치 혼선·pathspec 곡예·컨펌 굶김 실사고, 2026-07-28). 병렬성은 "여러 워커가 한 브랜치"가 아니라 "워커별 독립 브랜치"에서 나온다 — 워크트리가 안전한 대규모 병렬을 가능하게 한다.

- **메인 트리(`/{repo}`)는 `main`에 고정, stable home.** 워커 코드 작업 금지. 팀장이 여기서 git 교차검증(읽기)만.
- **각 PR/워커 = 자기 워크트리** `.claude/worktrees/wt-{ticket}` + 자기 브랜치(`fix|feat/PROJ-xxx`), **origin/main 기준 분기.**
- 커밋은 **feature 브랜치**에 → push → **PR → main 머지**(main은 ruleset 보호, direct push 불가). "approve = main 커밋"이 아니라 "approve = feature 브랜치 커밋".
- **분신(metamong1·2)·병렬 물량**에 최적 — 서로 다른 태스크·브랜치·워크트리라 완전 격리.

### ⚠️ 워크트리 셋업 체크리스트 (gitignore 파일이 워크트리엔 없다 — 필수)

워크트리는 git 체크아웃이라 **gitignored 파일이 딸려오지 않는다.** 생성 직후 반드시:
1. **env 복사**(Next.js/Nest는 `.env.local`을 읽는데 gitignore라 워크트리에 없음 → dev 서버 오동작, 예: 로그인 테스트버튼 사라짐). **앱이 늘면 이 목록도 늘어난다 — 프로젝트별 실제 앱 구성을 확인할 것**({app-repo}는 2026-08-04 PROJ-720으로 `apps/llm` 신설되어 3종):
   ```
   cp {repo}/{app-dir}/apps/web/.env.local  {wt}/{app-dir}/apps/web/.env.local
   cp {repo}/{app-dir}/apps/api/.env.local  {wt}/{app-dir}/apps/api/.env.local
   cp {repo}/{app-dir}/apps/llm/.env.local  {wt}/{app-dir}/apps/llm/.env.local
   ```
   - ⚠️ **Redis 등 공유 백킹서비스를 쓰는 프로젝트는 키 네임스페이스를 워크트리별로 분리**해야 병렬 기동이 서로 간섭하지 않는다({app-repo}: `REDIS_PREFIX=local:{ticket}`, api·llm 양쪽 동일 값). 프로젝트별 상세 절차는 `{프로젝트}/.claude/team/agents/_local-runtime.md`에 두고 팀원 애든덤에서 참조시킨다.
2. **`.claude/team`**(briefs/confirm/reports)도 gitignore → 워크트리에 없음. **메인 트리 절대경로**로 접근(`/{repo}/.claude/team/...`). request/reply/report는 메인 트리 쪽에 쓴다.
3. **node_modules — 프로젝트 레이아웃에 따라 다르다. 확인하고 브리프에 명시할 것.**
   - `node_modules`가 **레포 루트**에 있으면: 워크트리를 `.claude/worktrees/`(레포 하위)에 두면 Node 모듈 해석이 위로 올라가 루트 것을 공유 → install 불필요.
   - `node_modules`가 **하위 디렉토리**에 있으면({app-repo}: `{app-dir}/` 하위): 위로 해석이 안 올라가 **워크트리마다 `pnpm install` 필요**. (2026-08-09 실측 — 기존 "루트 공유" 서술이 이 레이아웃에서 틀렸다.)
4. **Docker/Postgres·포트 공유** — 로컬 Postgres(5432)는 하나만 기동(`docker-compose up -d`, Docker 데몬 먼저). dev 서버는 메인 트리 것과 포트 겹치면 종료 후 하나만.
5. Node 버전 = `.nvmrc`(22) 준수(`nvm use 22`).

> 팀장은 워크트리 배분 시 브리프에 "wt-{ticket} 생성 + 위 셋업"을 명시. 워커 페르소나 스킬도 이 체크리스트를 참조한다.

## 컨펌 신호 프로토콜 (탭 모드 백그라운드 통신, 2026-07-12)

커밋 전 컨펌을 사람이 탭을 오가며 전달하지 않고, **파일 신호 + 백그라운드 감시**로 팀장 세션에 모은다. 팀 모드(teammate 스폰)에서는 이 프로토콜 대신 자동 메시지 배달을 쓴다.

**신호 디렉토리**: `{프로젝트}/.claude/team/confirm/` (없으면 작성자가 `mkdir -p`)
- `{인스턴스명}.request.md` — **팀원 작성**. 유형(`CONFIRM`/`BLOCKED`/`DISCUSS`) + 태스크 번호 + 한일 요약 + 간략 테스트 플랜 + 변경 파일 목록. 꼬부기는 스크린샷 경로 포함. 인스턴스명은 보고 파일과 동일 규칙(`pairi`, `metamong2` 등). **`DISCUSS`(2026-07-22 신설)** = 브리프 지시가 기술적으로 불합리하다고 판단될 때 구현 전에 근거(공식문서·측정치)+대안을 제시하는 논의 요청 — 팀장은 근거를 검토해 reply에 `APPROVE`(대안 채택, 수정 브리프 포함) 또는 `FIX`(원안 유지, 이유 명시)로 답한다.
- 🔴 **워커가 "런타임 검증을 못 했다"고 보고하면, 팀장이 직접 확인하기 전에는 push를 승인하지 않는다 (2026-08-12 명문화).** 워커는 포트 점유·kill 권한 등으로 실제 클릭 스루를 못 하는 경우가 많고, 그때 **"컴포넌트 테스트가 흐름을 시뮬레이션한다"는 설명은 검증을 대체하지 못한다.** 테스트 하네스는 실환경과 다른 전제(예: 매번 새 QueryClient) 위에서 돌아 **실환경에서만 나는 버그를 구조적으로 못 잡는다.**
  - **실사고(2026-08-12)**: PROJ-1002 status 조회 API에서 `staleTime: Infinity`가 React Query 캐시 때문에 재마운트 시 재조회를 막았다. 워커가 "로컬 클릭 스루 못 함"을 명시했고 팀장이 "내가 직접 한다"고 답해놓고 **하지 않은 채 push를 승인** → preview에서 사용자가 발견. web 테스트 589건 전부 통과했는데도 깨진 이유는 **테스트가 매번 새 QueryClient로 시작해 캐시 생존 시나리오를 재현하지 못했기 때문**이다.
  - 팀장이 직접 확인할 수 없는 상황이면 **push하지 말고 사용자에게 확인을 요청**한다. "일단 올리고 preview에서 본다"는 그 자체로 게이트를 건너뛰는 것이다.
- ⚠️ **`APPROVE`는 "커밋" 게이트다 — push·PR 승인이 아니다 (2026-08-05 명문화).** 팀장은 reply에 **"커밋까지만"**을 기본으로 명시하고, **push·PR은 사용자 스모크 통과 후 별도 지시**로 분리한다. 워커 브리프의 절차도 `⑦커밋 → ⑧보고`에서 끝내고 **PR 생성을 워커 자율에서 제외**한다. (근거: 운영 모델의 "적정 단위 + **모든 스모크 완료** 시 PR 제안 → 사용자 컨펌 → PR". 2026-08-05 실사고 — 팀장이 마감 압박과 "선행조건이라 급하다"를 이유로 APPROVE reply에 "커밋→push→PR까지 바로"를 묶어 승인해, **사용자 스모크 없이 PR 3건이 올라감**. 자동 검증(테스트·빌드·린트)과 스크린샷은 스모크를 대체하지 못한다 — 실제 브라우저 흐름에서만 드러나는 회귀가 있고, 스모크 없이 머지되면 그걸 잡을 마지막 기회가 사라진다.)
- `{인스턴스명}.reply.md` — **팀장 작성**. 첫 줄 `APPROVE` 또는 `FIX`, FIX면 보완 지시 포함. **(2026-07-13 확장)** `APPROVE`인 경우 `---` 구분선 뒤에 `NEXT:` 섹션으로 **다음 태스크 브리프 전문**을 실을 수 있다(선택) — 의존성이 풀려 있고 다음 배분이 확정됐을 때만. FIX에는 NEXT를 싣지 않는다(보완 먼저).
- 사이클 종료 시 **팀원이 두 파일 모두 삭제** (잔여 파일 = 미처리 신호). 단일 작성자 원칙 유지: request는 팀원만, reply는 팀장만 쓴다.

**팀원 흐름**: ⑤검증 통과 → request 작성(채팅에도 같은 내용 출력) → 감시 명령을 **백그라운드로 실행**해 reply 대기 (생성되면 세션이 깨어난다):

```bash
f=".claude/team/confirm/{인스턴스명}.reply.md"; for i in $(seq 1 120); do [ -f "$f" ] && exit 0; sleep 15; done; exit 1
```

- `APPROVE` → 커밋 → 보고 파일 갱신 → 신호 파일 2개 삭제 → **reply에 `NEXT:` 브리프가 있으면 바로 착수**(새 사이클), 없으면 **아래 브리프 폴 루프를 지금 이 자리에서 다시 `run_in_background: true`로 실행**(⚠️ "브리프 대기"는 상태가 아니라 이 커맨드를 실행하는 행동이다 — 리스너 없이 그냥 멈추지 마라):
  ```bash
  b=".claude/team/briefs/{인스턴스명}.md"; h=$(md5 -q "$b" 2>/dev/null||md5sum "$b"|cut -d' ' -f1); for i in $(seq 1 240); do n=$(md5 -q "$b" 2>/dev/null||md5sum "$b"|cut -d' ' -f1); [ "$n" != "$h" ] && exit 0; sleep 15; done; exit 1
  ```
- `FIX` → 신호 파일 2개 삭제 → 보완 → 재검증 → 새 request로 재요청
- exit 1(30분 타임아웃) → 채팅에 "컨펌 대기 중" 상태를 알리고 감시 재시작하되, **연속 타임아웃마다 감시 시간을 2배로**(30분→1시간→2시간, 최대 4시간 — `seq` 상한을 240/480/960으로) 늘려 자리 비움 시 공회전을 막는다. 사용자가 채팅으로 직접 컨펌을 줘도 동일하게 처리(수동 fallback 호환).

**커밋 게이트 훅 (2026-07-27 신설, 2026-08-06 버그 확정)**: 파이리·메타몽 세션은 페르소나 스킬 frontmatter 훅(`hooks/gate-commit.sh`)이 `git commit`을 기계적으로 차단한다 — APPROVE reply가 있거나 `.claude/team/confirm/commit-waiver` 파일이 있을 때만 통과. **"컨펌 생략" 태스크 배분 시 팀장이 waiver 파일을 만들고, 해당 태스크 커밋 완료 보고 후 삭제한다.** 허브 문서(TASKS/PROGRESS) Edit/Write 차단 훅은 전 팀원 적용.

⚠️ **확정된 버그(2026-08-06, 소스 코드 확인) — 인스턴스를 구분하지 않는다.** `gate-commit.sh`의 통과 조건이 `glob.glob('*.reply.md')`로 **`confirm/` 안의 아무 reply.md나** 첫 줄이 `APPROVE`면 통과시킨다. 호출한 워커 자신의 `{인스턴스}.reply.md`인지 전혀 확인하지 않는다. **재현 경로**: 사이클 종료 시 워커가 신호 파일 삭제를 깜빡하거나(위 브리프 폴 재무장 갭과 동일 계열 문제 — 사이클 종료 처리가 안 끝난 채 다음으로 넘어감), 팀장이 다음 지시를 준비하는 사이 잠깐 남아있는 **다른 인스턴스의 옛 APPROVE reply.md 하나만 있어도** 그 순간 커밋하는 **아무 워커나** 통과된다. 2026-08-06에 메타몽2·파이리2 각각 최소 1회 APPROVE 이전에 커밋이 먼저 찍힌 게 이 버그로 설명된다(정확히 그 시점에 다른 인스턴스의 잔여 reply.md가 디렉토리에 있었음).
**고칠 방향(다음 성찰 루틴에서 구현)**: 훅이 인스턴스를 모른다는 게 근본 제약이다 — 가장 안전한 수선은 **매칭 성공 시 그 reply.md(+짝 request.md)를 훅이 직접 삭제**해 1회용으로 소비하는 것(워커의 "사이클 종료 시 삭제" 기억에 기대지 않음). 단 커밋 이후 워커가 reply.md 내용을 보고 작성에 다시 참조할 수 있어(현재 프로토콜 순서: 커밋→보고→삭제) 삭제 타이밍을 보고 작성 이후로 늦추거나 프로토콜 순서 자체를 재검토해야 한다 — 섣불리 훅에서 즉시 삭제하면 다른 워크플로우를 깰 수 있으니 실제 코드 변경 전에 설계 확인 필요.

**팀장 흐름 (감시 모드 — 탭 모드 기본 ON, 사용자가 끄라면 OFF)**: 배분 완료 후 감시 명령을 **백그라운드로 실행**:

```bash
# ⚠️ zsh는 매칭 없는 글롭이 fatal("no matches found") — 반드시 find 기반으로 (bash 글롭 금지)
for i in $(seq 1 240); do while IFS= read -r f; do [ -n "$f" ] && [ ! -f "${f%.request.md}.reply.md" ] && echo "$f" && exit 0; done < <(find .claude/team/confirm -name "*.request.md" 2>/dev/null); sleep 15; done; exit 1
```

- request 감지 → **git diff 교차검증** → 사용자에게 한일 요약+테스트 플랜 제시 → 사용자가 테스트하고 팀장과 판단 → reply 작성 → 감시 재시작
- `BLOCKED` request는 컨펌이 아니라 의사결정 요청 — 필요한 결정을 사용자와 정리해 reply에 지시로 담는다. `DISCUSS` request는 기술 논의 요청 — git diff 검증이 아니라 **근거 대 근거 판단**(필요 시 팀장이 공식문서 직접 확인)으로 처리한다.
- exit 1(60분 타임아웃) → 진행 상황 요약 후 감시 재시작하되 팀원과 동일하게 **백오프**(1시간→2시간→4시간). 사용자가 돌아와 말을 걸면 그 시점에 상태 보고.

**⚠️ 코파일럿 워커 폴링 특칙 (2026-07-22 — "폴링이 자꾸 멈추는" 문제의 원인·대책)**

Copilot CLI/SDK는 **세션 idle 타임아웃 ~30분**이 있어(공식 세션 퍼시스턴스 문서 + copilot-sdk#824 "35분 후 행") 오래 조용한 세션이 정리·행 상태가 된다. 우리 표준 폴링의 **백오프(30분→1·2·4시간)가 이 한도를 넘겨** 세션이 죽고, 깨어나도 응답이 없던 것. 대책:

1. **코파일럿 워커는 폴링 윈도우를 25분 이하로**: `seq 1 100`×15초(=25분). 타임아웃(exit 1)마다 **백오프 없이 즉시 같은 25분 윈도우로 재무장** — 주기적 깨어남 자체가 idle 타이머를 리셋해 세션을 살린다. (클로드 워커는 기존 백오프 유지 — 이 제한이 없다.)
2. **광범위 프로세스 킬 금지**: `pkill node` 류는 Copilot CLI 자기 프로세스를 죽여 세션이 통째로 사라진다(copilot-cli#3033). 서버 재시작은 반드시 `lsof`로 PID 특정 후 그 PID만 kill.
3. **그래도 멈추면(세션이 이미 정리된 경우) 복구는 한 마디**: 사용자가 해당 탭에 **"이어서"**라고 치면 워커는 ①자기 브리프 파일 ②자기 reply 파일을 순서대로 읽고 미처리분부터 재개 + 폴링 재무장한다 — 이것이 표준 재개 키워드(전 워커 공통, 클로드에도 무해).
4. 팀장은 코파일럿 워커 브리프/시작 프롬프트에 폴링 명령을 넣을 때 `seq 1 100` 버전으로 넣는다.

**주의**
- 컨펌 대기 중 워킹트리에 미커밋 변경이 체류한다 → 병렬 배분 시 **파일 경로 비겹침**이 더욱 중요.
- 게이트 강도는 팀장이 배분 시 결정: 런타임 확인이 불필요한 태스크는 브리프에 "컨펌 생략" 명시 가능.
- **토큰 특성**: 폴링 루프는 셸 프로세스라 토큰 0. 토큰은 세션이 깨어나는 턴에만 들며(이벤트 깨어남은 수동 전달 시에도 발생했을 턴이라 순증가 없음), 유일한 오버헤드는 타임아웃 공회전 — 위 백오프가 그 상한을 묶는다. 장시간 자리를 비울 예정이면 팀원에게 "감시 멈추고 대기"를 지시해도 된다(파일은 남아 있으므로 복귀 후 수동 처리 가능).

## 운영 모드 (자동화 수준, 2026-07-13 개정 2)

배분 시작 전 팀장이 사용자와 모드를 확인한다. 기본은 게이트 ON. **유일한 축은 컨펌 게이트 on/off** — 프로바이더(코파일럿/클로드)는 운영 모드가 아니라 "모델 배분" 디테일일 뿐이다(model-guide 소관).

| 모드 | 컨펌 게이트 | 용도 |
|---|---|---|
| **기본: 게이트 ON (자동)** | 컨펌 신호 프로토콜 완전 자동 — 워커가 **프로바이더 무관하게** 브리프의 백그라운드 폴링 루프로 reply를 자동 감지(코파일럿도 동일). 팀장이 request 자동 감지·판단, 사용자는 팀장 세션에서 테스트·판단만 | 상시 기본값 |
| **야간 무인: 게이트 OFF** | **컨펌 게이트 생략** + propose-don't-perform: 산출물은 별도 브랜치 커밋·PR 초안·보고서까지만, main 머지·배포 금지. 다음 날 팀장 세션 기력회복 절차에 "밤 산출물 검증" 포함 | 읽기·제안형 태스크만 (리서치, 문서 드리프트 스캔, 의존성 감사, 기계적 대량 변경 초안) |

- **코파일럿/클로드 무관하게** request 작성·reply 감지 경로가 동일(`.claude/team/confirm/`) — 워커가 브리프의 폴링 루프를 스스로 돌려 reply가 생기면 세션이 깨어난다. **사람 릴레이 불필요** (2026-07-13 실측: 코파일럿 워커가 브리프 폴링 루프를 자율 실행해 reply 자동 감지 확인 → 이전 "코파일럿 백그라운드 미지원" 조사 노트 폐기). 수동 채팅 컨펌은 여전히 fallback으로 호환.
- 프로바이더 혼용은 model-guide의 모델 배분 문제 — 회사 업무는 코파일럿 우선(토큰 소진), 필요 시 클로드. 게이트 자동화와 독립.
- 야간 무인 적합/부적합 기준·안전장치 4겹: `~/Desktop/agent-system-upgrade/reports/01-ecosystem-research.md` 5절 참조. 아직 파일럿 전 — 첫 실행은 위험 낮은 리포트형 태스크 1건으로.

## 검증·체크포인트

- 팀장은 보고를 **git으로 교차검증** (`git show --stat`, grep) 후 TASKS 갱신.
- 체크포인트 검증(테스트 전체/빌드/E2E)은 팀원에게 명령, 팀장은 결과 확인.
- 런타임 검증(LLM 실연, 외부 서비스 연동)은 자동 검증 한계를 명시하고 **사용자 직접 확인 항목**으로 분리.
- **스모크 핸드오프 표준 3종 세트**(2026-07-14 신설 → 2026-07-28 확장): 사용자가 "스모크하겠다" 또는 "시나리오 줘"라고 하면 팀장이 **항상 아래 3개를 한 번에** 제공한다. 서버 재기동은 테스트 스위트 실행이 아닌 환경 준비라 팀장 읽기전용 원칙과 무관.
  1. **시나리오에 맞게 서버 기동**: 검증 대상 코드가 있는 트리에서 기동한다 — **커밋 전 변경이면 그 워크트리**(`.claude/worktrees/wt-{ticket}`)에서, 머지 후면 메인 트리에서. 셋업: **인프라 컨테이너 확인**({app-repo}: `docker compose up -d postgres redis` — 5432·6379) → 대상 트리 `env.local` **전 앱분**(web+api+llm) 없으면 메인에서 복사 → 포트 잡은 stale 서버 종료 → 대상 트리에서 **전 앱 기동**({app-repo}: `pnpm nx serve llm`(6060)·`serve api`(8080)·`dev web`(3000))을 **`run_in_background: true`로** → 포트 리스닝 + 로그의 "Nest application successfully started"/"Ready" 확인 → **기동 시각 명시**(dev api는 HMR 없어 커밋 자동반영 X, 이 시각 이후 요청만 유효). `NEXT_PUBLIC_AUTH_MODE=dev` 확인(로그인 테스트 버튼).
     - ⚠️ **런타임이 쪼개지면 기동 목록도 늘어난다**({app-repo}는 2026-08-04 PROJ-720으로 llm pod 분리 — api만 띄우면 LLM 경로가 조용히 죽는다). 앱 하나를 빠뜨린 채 "환경 준비 완료"라고 넘기면 스모크가 통째로 무효가 되므로, **프로젝트별 기동 절차는 `_local-runtime.md`에 문서화하고 팀장이 핸드오프 때 그 파일 기준으로 점검**한다.
  2. **로그 tail 명령 동봉**: 사용자가 원하면 직접 볼 수 있게 백/프론트 로그 파일 tail 명령을 같이 준다 — `tail -f {api background output 경로}` / `tail -f {web background output 경로}`(백그라운드 태스크 output 파일 경로). 이상 발생 시 팀장이 즉시 그 로그를 까서 진단.
  3. **체크 시나리오**: 브라우저에서 사용자가 밟을 항목(로그인→기능→기대결과)과, 그중 **팀장이 DB/git으로 확인할 항목**(예: `graph_sessions` row 쿼리)을 구분해 제시.
  4. **⭐ 바로 쓸 수 있는 기존 데이터**(2026-08-11 신설, 사용자 요청): 시나리오를 밟을 **실제 프로젝트·케이스를 DB에서 찾아 함께 제시**한다. 프로젝트명 + URL(또는 project_id) + 그 데이터가 시나리오에 맞는 근거(예: "아키텍처 문서 7개·Fail 12건·최신 run=3")까지. **사용자가 매번 새 프로젝트를 만들게 하지 마라** — 시연·스모크에서 가장 반복되는 낭비다. 조건에 맞는 데이터가 없으면 "없음 + 신규 생성 필요"를 명시한다.
     - 조회 예: `docker exec {postgres} psql -U postgres -d {db} -t -A -F$'\t' -c "SELECT ..."` — 시나리오가 요구하는 선행 상태(상태값·파일 존재·판정 결과 등)를 조건에 넣어 찾는다.
  - (PROJ-677 스모크가 stale 서버로 무효화된 사고에서 규칙화. 워크트리 도입 후 "어느 트리에서 기동?"이 새 마찰점이라 트리 선택을 명문화.)

  3. **대형(M+) 태스크 착수 직전**: 여유 컨텍스트 확보
- **연속성 원칙**: 세션은 소모품, 상태는 파일에 — 정체성(`~/.claude/agents/{name}.md`), 이력(`reports/{name}.md`), 프로젝트(TASKS/PROGRESS), 코드(git log). 이 4곳만 충실하면 세션이 몇 번 바뀌어도 이어진다. 그래서 **보고 파일 기록은 생략 금지** (다음 세션의 나를 위한 기록).
- 팀장 브리프의 "선행 커밋 SHA 명시" 규칙이 세션 리셋 안전망을 겸한다 (기력회복 직후에도 기준점 명확).

- **주 후반 대형 배분 전 `/usage`로 주간 게이지 확인** — 주간 한도는 "전체 모델 풀"과 "모델별 풀"이 따로 돈다(상세: model-guide.md "맥스 플랜 한도 구조"). 전체 풀이 임박하면 워커 물량을 코파일럿으로 오프로드(회사 업무 우선 소진 원칙과 동일 방향).
- **성찰 루틴에 사용량 점검 편입**: 체크포인트 성찰 시 `/usage`에서 모델별 소비 비중을 보고, Opus 비중이 과반이면 라우팅(팀장 세션 길이·워커 격상 판단)을 재점검.
- **Fable/Opus 세션 종료 시 `/model sonnet` 복귀** — `/model` 선택이 다음 세션 기본값으로 영속되기 때문(상세: model-guide.md "모델 선택 영속성").

## 야간 자동화 운용 (2026-07-22 신설 — 팀장 소관)

> 목적: 사용자 워라밸 — 밤에는 사람 없이 돌아가는 것만 돈다. 자동화 도구의 평가·등록·운용은 배분 판단의 연장으로 **팀장 책임**. 배경·전체 그림: `plans/worklife-automation-proposal.md`.

- **가드레일 (채택됨)**: ①야간 = 자동화 전용, 산출물 검증은 아침 팀장 루틴 ②저녁 스택 등록은 퇴근 전 10분 ③밤 폰 개입(Remote Control)은 컨펌 1~2회 상한 ④리셋 시각 정렬은 스케줄러가 담당 — 사람이 기억하지 않는다.
- **/schedule 클라우드 루틴** (조사 2026-07-22): Anthropic 클라우드에서 도는 격리 세션 — cron(최소 1시간 간격, UTC) 또는 1회 실행, 모델 선택 가능(기본 Sonnet 5), GitHub 레포 체크아웃 기반. **로컬 접근 불가**(dev 서버·DB·로컬 파일 X) → 조사/문서/리뷰/PR초안형만. ⚠️ **선행 조건: 대상 레포 GitHub 연결 필요**(`/web-setup` 또는 Claude GitHub App 설치 — 회사 org 레포는 org 관리자 승인이 필요할 수 있음). 루틴 프롬프트는 zero-context 전제로 자기완결로 작성(팀장). 삭제는 claude.ai/code/routines에서만.
- **리밋 자동 재개 = `claude-auto-retry`** (파일럿 후보): `npm i -g claude-auto-retry` — tmux 기반으로 리밋 메시지를 감지해 리셋 시각까지 대기 후 "continue" 자동 입력. **야간 워커 탭 한정**(팀장 탭 미적용 — 주간 한도 소진 가속 방지), 워커 탭을 tmux 안에서 돌려야 함. 대안: unsnooze(멀티 세션 일괄), claude-auto-resume. 첫 파일럿은 야간 무인 배치 1회에 워커 1탭만.
- **로컬 머신 상시 대기(Remote Control용)**: 뚜껑 열어둠 + 전원 연결 + "디스플레이 꺼짐 시 자동 잠자기 방지"가 기본. 뚜껑을 닫아야 하면 `sudo pmset -a disablesleep 1`(원복 `0`) — 전원 연결 필수, 가방 보관 금지(발열). VPN은 야간에 끊길 수 있음 → 야간 산출물은 로컬 커밋까지(push는 아침) 원칙 유지.

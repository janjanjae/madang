**팀원 흐름**: ⑤검증 통과 → request 작성(채팅에도 같은 내용 출력) → 감시 명령을 **백그라운드로 실행**해 reply 대기 (생성되면 세션이 깨어난다):

```bash
f=".claude/team/confirm/{인스턴스명}.reply.md"; for i in $(seq 1 120); do [ -f "$f" ] && exit 0; sleep 15; done; exit 1
```

- `APPROVE` → 커밋 → 보고 파일 갱신 → 신호 파일 2개 삭제 → **reply에 `NEXT:` 브리프가 있으면 바로 착수**(새 사이클), 없으면 **아래 브리프 폴 루프를 지금 이 자리에서 다시 `run_in_background: true`로 실행**(⚠️ "브리프 대기"는 상태가 아니라 이 커맨드를 실행하는 행동이다 — 리스너 없이 그냥 멈추지 마라):
  ```bash
  b=".claude/team/briefs/{인스턴스명}.md"; h=$(md5 -q "$b" 2>/dev/null||md5sum "$b"|cut -d' ' -f1); for i in $(seq 1 240); do n=$(md5 -q "$b" 2>/dev/null||md5sum "$b"|cut -d' ' -f1); [ "$n" != "$h" ] && exit 0; sleep 15; done; exit 1
  ```
- `FIX` → 신호 파일 2개 삭제 → 보완 → 재검증 → 새 request로 재요청

루프는 계속 돌아 **request를 감지하고도 알림 없이 타임아웃(exit 1)** 한다. 실사고: 파이리 DISCUSS
request가 16:29에 올라왔는데 감시가 못 잡고 60분 뒤 타임아웃 — 워커가 직접 cross-session 메시지를
보내지 않았으면 그대로 묻혔다. **간헐적으로 동작해 보이는 게 더 위험하다**(셸·플랫폼에 따라 서브셸
여부가 갈린다). 위 교체본처럼 **감지 결과를 변수로 받아 루프 바깥에서 판단**할 것.

- request 감지 → **git diff 교차검증** → 사용자에게 한일 요약+테스트 플랜 제시 → 사용자가 테스트하고 팀장과 판단 → reply 작성 → 감시 재시작
- `BLOCKED` request는 컨펌이 아니라 의사결정 요청 — 필요한 결정을 사용자와 정리해 reply에 지시로 담는다. `DISCUSS` request는 기술 논의 요청 — git diff 검증이 아니라 **근거 대 근거 판단**(필요 시 팀장이 공식문서 직접 확인)으로 처리한다.
- exit 1(60분 타임아웃) → 진행 상황 요약 후 감시 재시작하되 팀원과 동일하게 **백오프**(1시간→2시간→4시간). 사용자가 돌아와 말을 걸면 그 시점에 상태 보고.

**⚠️ 코파일럿 워커 폴링 특칙 (2026-07-22 — "폴링이 자꾸 멈추는" 문제의 원인·대책)**

Copilot CLI/SDK는 **세션 idle 타임아웃 ~30분**이 있어(공식 세션 퍼시스턴스 문서 + copilot-sdk#824 "35분 후 행") 오래 조용한 세션이 정리·행 상태가 된다. 우리 표준 폴링의 **백오프(30분→1·2·4시간)가 이 한도를 넘겨** 세션이 죽고, 깨어나도 응답이 없던 것. 대책:

1. **코파일럿 워커는 폴링 윈도우를 25분 이하로**: `seq 1 100`×15초(=25분). 타임아웃(exit 1)마다 **백오프 없이 즉시 같은 25분 윈도우로 재무장** — 주기적 깨어남 자체가 idle 타이머를 리셋해 세션을 살린다. (클로드 워커는 기존 백오프 유지 — 이 제한이 없다.)
2. **광범위 프로세스 킬 금지**: `pkill node` 류는 Copilot CLI 자기 프로세스를 죽여 세션이 통째로 사라진다(copilot-cli#3033). 서버 재시작은 반드시 `lsof`로 PID 특정 후 그 PID만 kill.
3. **그래도 멈추면(세션이 이미 정리된 경우) 복구는 한 마디**: 사용자가 해당 탭에 **"이어서"**라고 치면 워커는 ①자기 브리프 파일 ②자기 reply 파일을 순서대로 읽고 미처리분부터 재개 + 폴링 재무장한다 — 이것이 표준 재개 키워드(전 워커 공통, 클로드에도 무해).
4. 팀장은 코파일럿 워커 브리프/시작 프롬프트에 폴링 명령을 넣을 때 `seq 1 100` 버전으로 넣는다.

**🔴 코파일럿 워커 기동 실측 (2026-08-31 — 세 가지가 전부 틀려 있었다)**

`go-{이름}-cop` 셸 함수(`~/Desktop/pokemon-agent-team/claude/shell/go-functions.zsh`)로 띄운다. 그날 고친 것:

| 항목 | 틀렸던 것 | 맞는 것 |
|---|---|---|
| 페르소나 | 프롬프트 첫 토큰 `/pairi` | `--agent pairi` — **코파일럿에 `/pairi` 슬래시는 없다**(`copilot help commands`: `/agent [name]`뿐). 텍스트로 흘러 페르소나가 안 붙었다 |
| 프롬프트 | pbcopy → 사람이 Cmd+V | `-i "<프롬프트>"` (CLI 1.0.82부터. 구 주석의 "초기 프롬프트 인자 없음"은 폐기) |
| 도구 | 에이전트 frontmatter `tools: all` | **`tools:` 줄 삭제**. 파서가 `s.tools \|\| ["*"]` — 배열이 아니면 필터가 오작동해 `skill`·`sql` 2개만 남는다 |

- **모델은 ID 전체로**: `GO_MODEL=claude-opus-5` (Claude 별칭 `opus`/`sonnet`은 안 먹는다). 가용 ID 실사용 이력: `sqlite3 ~/.copilot/session-store.db "select distinct model from assistant_usage_events;"`

- 🔑 **원본은 `~/.claude/agents/*.md`, 코파일럿 파일은 생성물이다.** 생성물만 고치면 `sync_claude_team` 다음 실행에서 되돌아간다 — 변환 규칙(`~/Desktop/pokemon-agent-team/copilot/skills/sync_claude_team/manifest.md`)을 같이 고쳐야 한다. 2026-08-31의 `tools: all` 장애가 정확히 그 매니페스트 규칙에서 나왔다.

**주의**
- 컨펌 대기 중 워킹트리에 미커밋 변경이 체류한다 → 병렬 배분 시 **파일 경로 비겹침**이 더욱 중요.
- 게이트 강도는 팀장이 배분 시 결정: 런타임 확인이 불필요한 태스크는 브리프에 "컨펌 생략" 명시 가능.
- **토큰 특성**: 폴링 루프는 셸 프로세스라 토큰 0. 토큰은 세션이 깨어나는 턴에만 들며(이벤트 깨어남은 수동 전달 시에도 발생했을 턴이라 순증가 없음), 유일한 오버헤드는 타임아웃 공회전 — 위 백오프가 그 상한을 묶는다. 장시간 자리를 비울 예정이면 팀원에게 "감시 멈추고 대기"를 지시해도 된다(파일은 남아 있으므로 복귀 후 수동 처리 가능).

## 🔴 팀장 감시 명령 — `Monitor` persistent (2026-08-24 교체)

**구 방식(`Bash(run_in_background)`)은 폐기한다.** 백그라운드 배시는 **exit할 때만** 알림을 주므로 감지 즉시 죽고, 재무장이 수동이라 반드시 공백이 생긴다.

**2026-08-24 실측 — 컨펌 5건 중 감시가 잡은 건 1건:**

| 컨펌 | 올라옴 | 처리 | 지연 |
|---|---|---|---|
| 꼬부기 1차 | 14:28 | 14:32 | ✅ 4분 (감시 작동) |
| 메타몽 | 15:26 | 15:47 | 🔴 21분 |
| 꼬부기 2차 | 15:28 | 15:54 | 🔴 **26분** |
| 파이리 | 15:46 | 15:54 | 8분 |

**공백이 생긴 4가지 원인** — 전부 구조적이다:
1. **1회용** — exit해야 알림이 오니 감지 즉시 죽는다
2. 🔴 **조건 혼합** — 감시를 *"컨펌 OR PR 머지"*로 만들었더니 **머지로 발화하면서 컨펌 감시가 같이 죽었다.** 이후 40분 무방비, 그 사이 컨펌 3건이 쌓임
3. **재무장이 별도 스텝** — 하필 제일 잊기 쉬운 순간(reply 작성 중)에 해야 한다
4. **타임아웃 후 자동 재개 없음**

### 대체 명령

```
Monitor({
  description: "워커 컨펌 요청 + 워커 유휴/사망 감지 (.claude/team/)",
  persistent: true,
  command: <아래 스크립트>
})
```

```bash
cd <프로젝트 루트>
C=.claude/team/confirm; R=.claude/team/reports; B=.claude/team/briefs
seen=""; idle=""
while true; do
  # 1) 컨펌 대기 — request가 있는데 reply가 없거나 더 오래됨
  # 🔴 `for f in "$C"/*.request.md` 도 `for f in $(find ...)` 도 쓰지 마라 (2026-08-26 실사고 2건).
  #    전자: zsh는 매칭 0건이면 fatal → confirm/이 비면 감시가 즉사한다.
  #    후자: zsh는 unquoted 확장을 **단어분리하지 않아** request가 2개가 되는 순간
  #          개행이 붙은 한 덩어리가 되고 `-e`에서 조용히 탈락한다 → 컨펌을 통째로 못 본다.
  #    while read + 프로세스 치환은 **현재 셸에서** 돌아 seen/idle 누적도 살아남는다(파이프면 서브셸이라 날아간다).
  while IFS= read -r f; do
    [ -e "$f" ] || continue
    n=$(basename "$f" .request.md); rp="$C/$n.reply.md"
    if [ ! -f "$rp" ] || [ "$f" -nt "$rp" ]; then
      k="$n@$(md5 -q "$f" 2>/dev/null)"        # md5로 같은 요청 중복 알림 방지
      case "$seen" in *"|$k|"*) ;; *) echo "🔔 컨펌 대기: $n  ($(date +%H:%M))"; seen="$seen|$k|";; esac
    fi
  done < <(find "$C" -name '*.request.md' 2>/dev/null)
  # 2) 유휴 의심 — reports가 25분 이상 정지 + 대기 중인 컨펌 없음
  #    🔴 보고가 **현재 브리프보다 오래됐으면 건너뛴다** — 그건 "노는 중"이 아니라 "아직 기동
  #       안 함"이고, 팀장이 이미 아는 사실이라 알릴 값이 없다. 안 걸러내면 기동 전까지
  #       45분마다 워커 수만큼 반복 발화한다(2026-08-26).
  now=$(date +%s)
  for w in pairi kkobugi metamong; do
    rf="$R/$w.md"; bf="$B/$w.md"; [ -e "$rf" ] || continue
    [ -e "$bf" ] && [ ! "$rf" -nt "$bf" ] && continue   # 미기동 = 유휴 아님
    [ -f "$C/$w.request.md" ] && { case "$seen" in *"|$w@"*) continue;; esac; }
    m=$(stat -f %m "$rf" 2>/dev/null || echo "$now")
    gap=$(( (now - m) / 60 ))
    if [ "$gap" -ge 25 ]; then
      k="idle:$w:$(( gap / 25 ))"
      case "$idle" in *"|$k|"*) ;; *) echo "💤 유휴 의심: $w — reports ${gap}분 정지  ($(date +%H:%M))"; idle="$idle|$k|";; esac
    fi
  done
  sleep 20
done
```

### 규칙

- 🔴 **조건을 섞지 마라.** 컨펌 감시는 컨펌만. CI·머지·빌드는 **별도** `Bash(run_in_background)`(1회성 조건이라 그쪽이 맞다)
- **무장은 배분과 같은 턴에.** 별도 스텝으로 미루면 잊는다
- 세션당 1개면 충분하다 — 이미 떠 있으면 다시 무장하지 마라(중복 알림)
- `md5` 기준 중복 방지라, 워커가 request를 **갱신**하면 새 알림이 온다(의도된 동작)

### 알려진 오탐

- **유휴 판정이 `reports` mtime 기준**이라, 워커가 커밋했는데 보고를 아직 안 썼으면 유휴로 뜬다(2026-08-24 꼬부기 사례 — 이미 `fda5ca72` 커밋 상태였다). **알림을 받으면 워크트리 HEAD·미커밋을 먼저 확인**하고 판단할 것.
- 반대로 **팀장이 reply를 늦게 줘서 워커가 기다리는 것도 "유휴"로 잡힌다.** 이건 오탐이 아니라 **팀장 병목 신호**다 — 그때는 워커가 아니라 자신을 봐라.

# 야간 자동화 운용 (팀장 소관)

> `ways-of-working.md`에서 분리(2026-08-13). **야간 배치를 등록·운용할 때** 읽는다.

> 목적: 사용자 워라밸 — 밤에는 사람 없이 돌아가는 것만 돈다. 자동화 도구의 평가·등록·운용은 배분 판단의 연장으로 **팀장 책임**. 배경·전체 그림: `plans/worklife-automation-proposal.md`.

- **가드레일 (채택됨)**: ①야간 = 자동화 전용, 산출물 검증은 아침 팀장 루틴 ②저녁 스택 등록은 퇴근 전 10분 ③밤 폰 개입(Remote Control)은 컨펌 1~2회 상한 ④리셋 시각 정렬은 스케줄러가 담당 — 사람이 기억하지 않는다.
- **/schedule 클라우드 루틴** (조사 2026-07-22): Anthropic 클라우드에서 도는 격리 세션 — cron(최소 1시간 간격, UTC) 또는 1회 실행, 모델 선택 가능(기본 Sonnet 5), GitHub 레포 체크아웃 기반. **로컬 접근 불가**(dev 서버·DB·로컬 파일 X) → 조사/문서/리뷰/PR초안형만. ⚠️ **선행 조건: 대상 레포 GitHub 연결 필요**(`/web-setup` 또는 Claude GitHub App 설치 — 회사 org 레포는 org 관리자 승인이 필요할 수 있음). 루틴 프롬프트는 zero-context 전제로 자기완결로 작성(팀장). 삭제는 claude.ai/code/routines에서만.
- **리밋 자동 재개 = `claude-auto-retry`** (파일럿 후보): `npm i -g claude-auto-retry` — tmux 기반으로 리밋 메시지를 감지해 리셋 시각까지 대기 후 "continue" 자동 입력. **야간 워커 탭 한정**(팀장 탭 미적용 — 주간 한도 소진 가속 방지), 워커 탭을 tmux 안에서 돌려야 함. 대안: unsnooze(멀티 세션 일괄), claude-auto-resume. 첫 파일럿은 야간 무인 배치 1회에 워커 1탭만.
- **로컬 머신 상시 대기(Remote Control용)**: 뚜껑 열어둠 + 전원 연결 + "디스플레이 꺼짐 시 자동 잠자기 방지"가 기본. 뚜껑을 닫아야 하면 `sudo pmset -a disablesleep 1`(원복 `0`) — 전원 연결 필수, 가방 보관 금지(발열). VPN은 야간에 끊길 수 있음 → 야간 산출물은 로컬 커밋까지(push는 아침) 원칙 유지.

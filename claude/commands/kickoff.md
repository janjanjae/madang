# kickoff

새 스토리/에픽 착수 오케스트레이션 — Phase 설계 + PROGRESS.md 초기화.
**팀장 전용** (PROGRESS.md 초기화 = 허브 문서 작성. 팀원 사용 금지 — skill-guide 참조).

> 2026-07-26 리라이트: 구 모델표(glm-5.2·Pro 플랜 전제)·`/jira-story-fetch` 참조·"새 세션 붙여넣기 프롬프트" 패턴 제거 — 각각 model-guide.md, `/jira-story-cache`, 파일 기반 브리프(2026-07-14 전환)로 대체.

## Step 1: 상황 파악

다음을 사용자에게 물어보거나 인자로 받아라:
- Jira 스토리 번호 — 있으면 `/jira-story-cache PROJ-{n}`으로 캐시 생성 후 `.claude/stories/PROJ-{n}.md`를 읽는다. description·AC가 비면 `/jira-refine` 착수 전 모드를 먼저 안내.
- 없으면: 지금 하려는 작업이 뭔지 간단히 설명 요청.

## Step 2: 작업 성격 판단

| 유형 | 설명 | Phase 구성 |
|------|------|-----------|
| 신규 개발 | 없던 기능을 처음 만드는 것 | 설계 → 구현 → 검증 |
| 기존 코드 수정/개선 | 있는 코드를 변경하는 것 | **분석 → 설계 → 구현 → 검증** |
| 버그 수정 | 특정 에러/버그 해결 | 분석 → 구현 → 검증 |
| 단순 변경 | 설정, 텍스트, 소규모 수정 | 구현 → 검증 |

## Step 3: Phase별 목표 구체화

- **분석**: 어떤 코드를 읽어야 하는지, 파악해야 할 핵심 질문이 뭔지
- **설계**: 어떤 결정을 내려야 하는지, 태스크를 어떻게 쪼갤지 (`planning-and-task-breakdown` 활용)
- **구현**: 어떤 순서로 무엇부터 만들지 — **팀원 배분 단위**로 (병렬 가능하면 파일 경로가 안 겹치게 분리)
- **검증**: 완료 기준이 뭔지 (자동 검증 vs 사용자 직접 확인 항목 분리)

## Step 4: 모델·팀원 배분 전략

- 모델 배분은 `~/.claude/skills/teamleader/model-guide.md`가 SSOT — Phase별 권장 모델을 이 문서 기준으로 제안 (이 커맨드 안에 모델표를 두지 않는다: 이중 관리 방지).
- 팀원 배분은 `roster.md` 기준: 일반 구현·병렬 물량 → 메타몽(분신), 핵심·까다로운 슬라이스 → 파이리, UX 시안 → 꼬부기.

## Step 5: Phase별 브리프 초안 생성

각 Phase의 구현 태스크를 **팀원 브리프 초안**으로 작성한다 (배분 시 `.claude/team/briefs/{인스턴스}.md`로 전달 — 자기완결 원칙, ways-of-working "브리프" 절 참조).

브리프에 반드시 포함:
- 전체 작업 배경 (한 문단) + "왜 지금 이것부터"
- 이 태스크의 목표와 완료 기준 (AC 수준으로 구체적으로)
- 구체적으로 봐야 할 파일/모듈 (절대경로)
- 산출물 + 보고 양식, 권장 프로바이더·모델, 컨펌 생략 여부

> 팀 워크플로우 없이 혼자 진행하는 예외 세션에서는 브리프 초안을 그 세션의 작업 계획으로 그대로 쓰면 된다.

## Step 6: PROGRESS.md 초기화

`.claude/PROGRESS.md`를 이 작업 기준으로 초기화하라. TASKS.md 태스크 목록도 함께 설계(`planning-and-task-breakdown`).

## 출력 형식

```
## 작업 요약
[Jira 스토리 또는 목표 요약]

## 작업 유형
[신규/수정/버그/단순]

## Phase 구성
Phase 1: [목표]
Phase 2: [목표]
...

## 배분 계획
| Phase/태스크 | 팀원 | 모델 | 의존성 |
|---|---|---|---|

## 브리프 초안
### {팀원} — {태스크명}
[브리프 본문]
...
```

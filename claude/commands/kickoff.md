새 개발 작업을 시작하기 위한 오케스트레이터 역할을 수행한다.

> **팀장 패턴 연동** (`/teamleader` 워크플로우 사용 시): 이 스킬은 **팀장 전용**이다 (PROGRESS.md 초기화 = 허브 문서 작성).
> - Phase 3 구현은 "새 세션에 붙여넣을 프롬프트"가 아니라 **팀원(파이리/메타몽) 브리프**로 배분한다 — Step 5의 프롬프트 생성을 브리프 초안으로 대체.
> - Step 4 모델 전략은 아래 표 대신 `~/.claude/skills/teamleader/model-guide.md`를 우선 참조 (그쪽이 현행화 대상).

## Step 1: 상황 파악

다음을 사용자에게 물어보거나 인자로 받아라:
- Jira 스토리 번호 (있으면 /jira-story-fetch로 내용 가져오기)
- 없으면: 지금 하려는 작업이 뭔지 간단히 설명 요청

## Step 2: 작업 성격 판단

아래 기준으로 어떤 유형의 작업인지 분류하라:

| 유형 | 설명 | Phase 구성 |
|------|------|-----------|
| 신규 개발 | 없던 기능을 처음 만드는 것 | 설계 → 구현 → 검증 |
| 기존 코드 수정/개선 | 있는 코드를 변경하는 것 | **분석 → 설계 → 구현 → 검증** |
| 버그 수정 | 특정 에러/버그 해결 | 분석 → 구현 → 검증 |
| 단순 변경 | 설정, 텍스트, 소규모 수정 | 구현 → 검증 |

## Step 3: Phase별 목표 구체화

작업 성격에 맞게 각 Phase에서 무엇을 해야 하는지 구체화하라:

- **분석**: 어떤 코드를 읽어야 하는지, 파악해야 할 핵심 질문이 뭔지
- **설계**: 어떤 결정을 내려야 하는지, 태스크를 어떻게 쪼갤지
- **구현**: 어떤 순서로 무엇부터 만들지
- **검증**: 완료 기준이 뭔지

## Step 4: 모델 전략 제안

각 Phase에 맞는 모델 추천:
- 킥오프/워크플로우 관리: `use-claude` Sonnet
- 분석 (코드 대량 읽기): `use-glm` glm-5.2[1m] (토큰 한도 여유 + 1M 컨텍스트)
- 설계 (아키텍처 결정): `use-claude` Fable 5 또는 Opus 4.8
- 구현 (코딩): `use-glm` glm-5.2[1m] (Claude Pro 토큰 절감) 또는 `use-claude` Sonnet
- 검증: `use-claude` Sonnet

## Step 5: Phase별 시작 프롬프트 생성

각 Phase를 시작할 때 새 세션에 붙여넣을 프롬프트를 생성하라.
프롬프트에는 반드시 포함:
- 전체 작업 배경 (한 문단)
- 이 Phase의 목표
- 구체적으로 봐야 할 파일/모듈
- 산출물 (뭘 만들거나 채워야 하는지)

## Step 6: PROGRESS.md 초기화

.claude/PROGRESS.md를 이 작업 기준으로 초기화하라.

## 출력 형식

```
## 작업 요약
[Jira 스토리 또는 목표 요약]

## 작업 유형
[신규/수정/버그/단순]

## Phase 구성
Phase 1: [목표]
Phase 2: [목표]
...

## Phase별 시작 프롬프트
### Phase 1 프롬프트
[붙여넣기용 프롬프트]

### Phase 2 프롬프트
[붙여넣기용 프롬프트]
...
```

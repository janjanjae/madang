# skill-audit

스킬·커맨드·에이전트 인벤토리를 실제 파일 기준으로 전수 스캔하고, `~/.claude/REGISTRY.md`(개인 환경 원장)를 현행화한다.
**SSOT는 파일 시스템** — 레지스트리는 손으로 관리하는 목록이 아니라 스캔 결과에서 파생되는 문서다.

## 언제 사용하나

- 성찰 루틴의 일부로 **월 1회 또는 스프린트 종료 시** (팀장 세션에서)
- 스킬/커맨드를 새로 만들거나 폐기·이동했을 때 즉시
- "이 스킬 뭐더라" 같은 질문이 반복될 때 (레지스트리가 썩었다는 신호)

## 실행 절차

### 1. 전수 스캔

아래 위치를 스캔한다. **심링크 여부로 관리 주체를 구분**한다 (심링크 → pokemon-agent-team 레포 관리분, 실디렉토리/실파일 → 로컬 전용).

```bash
# 범용 (개인 글로벌)
ls -la ~/.claude/skills/ ~/.claude/commands/ ~/.claude/agents/

# 프로젝트 오버레이 (현재 프로젝트에서 실행 중일 때)
ls {프로젝트 루트}/.claude/skills/ {프로젝트 루트}/.claude/commands/ {프로젝트 루트}/.claude/agents/ 2>/dev/null
```

### 2. REGISTRY.md 대조 → 차이 감지

`~/.claude/REGISTRY.md`와 스캔 결과를 비교해 보고한다:

- **신규**: 파일은 있는데 레지스트리에 없음 → 분류(축 2개) 판정 후 등재
- **유령**: 레지스트리에 있는데 파일이 없음 → 삭제 또는 폐기 표기
- **이동**: 스코프가 바뀐 것 (예: 프로젝트 → 범용 승격, 레포 공유 → 개인 이관)

### 3. 항목별 판정 (skill-guide 상태 평가 방식 승계)

각 항목에 `유지 / 개정됨 / 신설 / 폐기 후보` 판정. 판단 기준:

- 최근 1개월 내 실제 사용 여부 (기억 + git log + 세션 이력)
- 팀 운영 규칙(ways-of-working)과 충돌 여부
- 더 나은 대체재 등장 여부
- **패치 노트 3개 이상 누적 여부** — 규칙 변경을 주석 추가로 때운 문서는 본문과 모순되기 시작한다(2026-07-25 kickoff 사례). 누적 시 "개정됨(리라이트 필요)" 판정

폐기 후보는 **즉시 삭제하지 않고** 레지스트리에 표기만 → 다음 audit에서도 미사용이면 그때 삭제 제안.

### 4. 트렌드 스캔 (선택 — 시간 여유 있을 때만)

웹서치 1회로 최근 뜨는 에이전트 스킬/방법론을 확인하고, 팀 배정 스킬(debugging, incremental 등)의 교체·보강 후보가 있으면 레지스트리 "검토 후보" 절에 메모. **즉시 도입하지 않는다** — 후보 등재까지만.

**상류 도입 스킬 diff 체크**: provenance.md가 있는 스킬(예: verification-before-completion)은 상류 레포의 해당 파일과 diff — 갱신이 있으면 검토 후 원본 그대로 재도입(커스터마이징 금지 방침).

### 5. 산출물 갱신

1. `~/.claude/REGISTRY.md` 갱신 (스캔 일자 명기)
2. 팀 배정 변화가 있으면 `claude/skills/teamleader/skill-guide.md` 표도 동기화
3. 레포 파일(skill-guide 등) 변경분만 레포에 커밋 (REGISTRY는 개인 로컬 — 커밋 대상 아님)

## 가드레일

- **읽기 + 레지스트리 갱신만** — 이 커맨드가 스킬 파일 자체를 수정·삭제하지 않는다 (폐기는 별도 승인 후)
- 프로젝트 오버레이 스킬은 목록화만 — 내용 평가는 해당 프로젝트 소관
- 비개발 개인 스킬(가계부 등)은 이름만 등재, 레포 동기화 대상에서 제외 유지

# 공개 전환 체크리스트 — private로 쓰다가 공개할 때

개인 프로젝트를 private로 편하게 쓰다가 공개할 때, 어떤 길을 고르고 단계마다 어떤 도구를 돌리는지 한 장으로 정리한다.
**기본 경로는 B(새 public 레포에 스냅샷 1커밋)다.** A(그 자리 전환)는 감사할 수 있을 때만 쓴다.

> 이 문서가 SSOT다. 실제 사례(경로 A, 며칠 걸림): `plans/release-runbook-v05.md` — 단계별 명령·중단 조건·되돌리기가 거기 있다.
> 예시 값은 `{owner}/{repo}`로 적었다. 사고 사례는 문자열이 아니라 **유형**만 쓴다(그 문자열을 다시 옮기면 이 문서가 새 유출원이 된다).

## 0. 어느 길로 갈까

| | **B. 새 레포로 공개 (기본)** | **A. 그 자리에서 전환** |
|---|---|---|
| 무엇을 올리나 | 코드 스냅샷 **1커밋** + 공개해도 되는 설계 문서 | 기존 레포의 히스토리·브랜치·이슈·PR 전부 |
| 히스토리 | 버린다(원 레포가 기록 보관용으로 남는다) | 재작성해서 보존 |
| 감사해야 하는 것 | **지금 보이는 파일만** | 모든 커밋·메시지·브랜치·태그·이슈·PR·코멘트·Actions 로그·릴리스 |
| 비용 | 몇 시간 | 며칠(리허설 + 런북) |
| 실수했을 때 | 공개 전이면 새 레포를 지우면 끝 | force-push·공개 이후엔 **되돌릴 수 없다**(클론·캐시) |
| 이슈·PR·스타 | 새로 시작 | 이어짐 |

**A를 쓰려면 아래가 전부 "예"여야 한다. 하나라도 아니면 B다.**

1. 히스토리 전체(메시지·author/committer 신원 포함)를 기계로 스캔할 수 있고, 그 결과를 사람이 판정할 시간이 있다.
2. 이슈·PR·코멘트·Actions 로그·릴리스·위키를 **전부** 읽고 감사할 수 있다.
3. 히스토리·이슈·스타를 보존할 이유가 실제로 있다(그냥 아깝다는 건 이유가 아니다).
4. 원본을 `--mirror` 백업으로 따로 보관하고 되돌리는 절차를 한 번 리허설했다.

## 1. private 기간 위생 규칙 (평소 이것만은)

공개 전환 비용은 **private 기간에 쌓인 것의 양**으로 결정된다.

1. **비밀값은 env에만 둔다.** 커밋·이슈·PR·코멘트·로그 어디에도 쓰지 않는다. 한 번 들어가면 히스토리에 영구히 남는다.
2. **설계 문서는 공개 가능한 톤으로 쓴다.** 나중에 그대로 가져갈 유일한 문서다. 회사명·동료 이름·내부 호스트·티켓 키를 "어차피 private니까" 하고 쓰지 않는다.
3. **이슈·PR 본문도 공개된다** — 경로 A에서는 그대로, 경로 B에서도 공개본을 보는 사람이 링크·인용을 통해 마주칠 수 있다. 코드 파일만 신경 쓰면 이슈에서 샌다.

**check-draft와 연결** (`claude/tools/sanitize/check-draft.sh`):

- `/issue-add`의 github 경로는 이슈 생성 전에 초안(제목+본문)을 자동으로 검사한다.
- 🔴 **단, 레포가 PRIVATE이면 검사를 건너뛴다**(설계상 — 공개될 일이 없으므로). 즉 private 기간에 쓴 이슈는 **검사된 적이 없다.** 경로 A에서 이슈를 따로 감사해야 하는 이유다.
- PR 본문·코멘트·`/issue-refine`의 본문 수정은 자동 검사가 없다. 공개 레포에 쓸 때는 직접 돌린다:
  ```bash
  printf '%s\n\n%s\n' "$TITLE" "$BODY" | {madang}/claude/tools/sanitize/check-draft.sh --repo {owner}/{repo}
  # exit 0 통과 · 1 걸린 줄(치환안 출력) · 2 검사 불가 — 2를 통과로 읽지 않는다
  ```

## 2. 도구 지도 — 무엇이 무엇을 보고, 무엇을 못 보나

| 도구 | 보는 것 | 못 보는 것 |
|---|---|---|
| `verify-tree.sh` | **워킹 트리**에서 치환표에 없는 회사·개인 식별 후보(일반형 6축) | 히스토리, 이슈·PR |
| `verify-history.sh` | **재작성한 히스토리**에 치환표 패턴·구 신원이 남았나, 커밋이 유실되지 않았나 | 🔴 **치환표가 모르는 문자열.** "치환표가 설명하는가"만 본다 |
| `check-draft.sh` | 텍스트(이슈·PR 초안, 임의 스트림)의 일반형 축 + 로컬 경로·계정명 + 개인 치환표 | 파일 위치(줄 번호는 입력 기준) |
| **독립 스캔**(아래 3절) | 표와 **무관하게** 사람이 아는 단어·일반형 축으로 히스토리·트리를 다시 훑는다 | — |

사용법·종료 코드는 `claude/tools/sanitize/README.md`.

## 3. 독립 스캔 — 치환표 밖을 잡는 단계 (이 교훈 하나만은 반드시)

**사고(2026-09, 유형만):** 치환표로 filter-repo를 돌리고 `verify-history`가 「전체 통과」를 냈는데도 **치환표에 없던 회사 문자열 6종이 히스토리에 남아 있었다.** 도구가 틀린 게 아니다 — `verify-history`는 처음부터 "표가 만든 변환이 빠짐없이 적용됐나"만 묻는다. **표가 불완전하면 표 기반 검사는 같이 불완전하다.**

그래서 공개 직전에는 **표를 모르는 눈**이 한 번 더 필요하다. 두 가지를 둘 다 한다:

**(가) 사람의 단어 목록(표에 넣지 않는다).** 공개되면 곤란한 단어를 기억에서 10개쯤 적는다 — 회사·조직 이름, 제품 코드명, 동료·고객 이름, 내부 호스트·도메인, 사내 도구 이름, 티켓 키 접두사. 이 목록은 **레포 안 어디에도 저장하지 않는다**(저장하는 순간 그 파일이 유출원이다).
```bash
# 히스토리 전체(메시지·diff·신원 포함)에서 하나라도 나오면 건수와 커밋을 본다
git log --all --format='%H' -G'단어1|단어2|단어3' | wc -l
git log --all -p --format='%an <%ae> | %cn <%ce>%n%B' | grep -ciE '단어1|단어2|단어3'
# 현재 트리
git grep -nIiE '단어1|단어2|단어3' | head -40
```

**(나) 일반형 축 스트림 스캔(`check-draft.sh` 재사용).** 히스토리 전체를 텍스트로 흘려 일반형 축(도메인·티켓 키·메일·토큰·로컬 경로·로컬 계정명)에 걸리는 줄을 센다. **치환표를 일부러 빼서(`CHECK_DRAFT_REPL=/nonexistent`) 표와 독립**으로 돌린다:
```bash
git log --all -p --format='%an <%ae>%n%cn <%ce>%n%B' \
  | CHECK_DRAFT_REPL=/nonexistent {madang}/claude/tools/sanitize/check-draft.sh \
  | grep '원문:' | sort | uniq -c | sort -rn | head -40
```
- 노이즈가 많다 — 일반형 축은 의도적으로 느슨하다(약 2만 줄 히스토리에서 수백 줄이 걸렸다). **0건을 기대하지 말고, 걸린 줄을 유형별로 사람이 판정**한다("실제 회사 정보 / 문서 속 설명용 예시 / 무해").
- 판정 후 "회사 정보"가 하나라도 나오면 **그 단계로 되돌아가** 표(또는 스냅샷)를 고치고 처음부터 다시 돌린다. 표를 고친 뒤 `verify-history`만 다시 돌리면 같은 함정에 다시 빠진다 — 독립 스캔도 다시.
- `--repo`를 안 주면 "PUBLIC으로 간주" 경고가 뜬다. 이 용도에선 정상이다.

## 4. 경로 B — 새 public 레포 (기본)

| # | 단계 | 명령·도구 | 🔴 중단 조건 | 되돌리기 |
|---|---|---|---|---|
| B0 | 준비 | 원 레포 `git status --short` 깨끗 · 올릴 기준 커밋(보통 `main`) 확정 · 새 레포 이름·소유자 확정 | 미커밋 변경이 있다 — 무엇을 올리는지 불분명해진다 | 관찰만 |
| B1 | 스냅샷 | 빈 디렉토리에 **추적 파일만** 꺼낸다: `git -C {원레포} archive HEAD \| tar -x -C {새디렉토리}` | `git archive`가 아니라 폴더 복사를 쓰려 한다 — gitignore된 `.env`·로컬 설정·팀 문서가 딸려온다 | 새 디렉토리를 지운다 |
| B2 | 문서 선별 | 가져갈 것은 **공개해도 되는 설계 문서**(architecture·ADR·README·사용법)뿐이다. 팀 문서(브리프·보고·컨펌·이슈 캐시)는 애초에 앱 레포 밖이다(`.claude/team/`은 gitignore) — 있으면 지운다. 계획·회고·세션 기록 문서는 기본적으로 제외 | 문서에 회사명·동료 이름·내부 URL이 있다 — 문서를 고친 뒤 계속 | 파일 삭제만 |
| B3 | 스캔 | 새 디렉토리에서 `git init -b main && git add -A` 후 `{madang}/claude/tools/sanitize/verify-tree.sh`(워킹 트리 후보) → 판정 · 이어서 **3절 독립 스캔 (가)**(`git grep`) | 후보 중 하나라도 "회사 정보"다 — 고치고 B3부터 다시. exit 2(치환표 없음)는 "검사 못 함"이지 통과가 아니다 | 아직 로컬 |
| B4 | README·LICENSE | README 첫 화면에 **무엇인지·설치·현재 한계**가 있다 · LICENSE가 있다(없으면 기본이 "모든 권리 보유"임을 알고 의도한 것인지 확인) · 개인 절대경로·계정·메일 없음 | README가 여전히 "초안/내부용" 표현이거나 개인 환경 경로를 안내한다 | 파일 수정 |
| B5 | 신원 + 커밋 | `git config user.name`/`user.email`이 **공개용 신원**(예: GitHub noreply 주소)인지 확인 후 1커밋: `git commit -m "chore: 초기 공개 스냅샷"` · `git log -1 --format='%an <%ae> / %cn <%ce>'` | author/committer에 회사·개인 메일이 찍힌다 — 커밋 전에 `user.email` 수정 | `git commit --amend --reset-author` (아직 push 전) |
| B6 | **private로** 생성·push | `gh repo create {owner}/{repo} --private --source . --remote origin --push` — 처음부터 public으로 만들지 않는다 | 계정이 의도한 소유자가 아니다(`gh auth status --active`) | 새 레포 삭제(`gh repo delete`) |
| B7 | 푸시된 것 재확인 | **원격에서 새로 클론**해 `verify-tree.sh` 한 번 더 + 3절 (가) · 파일 목록을 눈으로 본다 | 로컬과 다른 것이 올라갔다 | 새 레포 삭제 후 B1부터 |
| B8 | 🔴 **공개 전환 (되돌릴 수 없는 지점)** | `gh repo edit {owner}/{repo} --visibility public --accept-visibility-change-consequences` | **직전에 B7이 끝났는지 한 번 더 확인.** 공개 순간부터 누군가 클론할 수 있다 | `--visibility private`로 되돌릴 수 있지만 이미 가져간 사본은 못 되돌린다 |
| B9 | 공개 후 확인 | 아래 5절 | — | — |
| B10 | 원 레포 | 원 레포는 **private로 두고 기록 보관용**. README 맨 위에 한 줄: `공개본 → https://github.com/{owner}/{repo}` | 원 레포를 public으로 바꾸려 한다 — 그건 경로 A다 | 한 줄 삭제 |

> 팀 문서(`TASKS`·`PROGRESS`·브리프)는 공개 대상이 아니다. `.claude/`를 앱 레포 안에 두는 구성이라면 `.gitignore`에 이미 들어 있어야 하고, B1의 `git archive`는 추적 파일만 꺼내므로 따라오지 않는다 — 그래도 B3에서 눈으로 확인한다.

## 5. 공개 후 확인 (A·B 공통)

| | 확인 | 방법 |
|---|---|---|
| 1 | **로그인 없이 보인다** | `curl -s -o /dev/null -w '%{http_code}\n' https://github.com/{owner}/{repo}` → `200` (비로그인 기준이므로 브라우저 시크릿 창으로 한 번 더) |
| 2 | **기여 그래프("잔디")에 연결된다** | 최신 커밋을 웹에서 열어 **계정 아바타**가 뜨는지 본다 — 회색 기본 아이콘이면 author 이메일이 계정에 등록·인증되지 않은 것이다. 공개 전(B6 직후 / A의 push 직후)에 보는 게 좋다 |
| 3 | **첫인상(clone → install → 첫 명령)** | 임시 HOME에서만: `git clone https://github.com/{owner}/{repo}.git /tmp/fresh && cd /tmp/fresh && HOME=$(mktemp -d) ./install.sh` — 🔴 `HOME=$(mktemp -d)`를 빼면 실사용 환경의 심링크를 확인용 클론으로 갈아끼운다 |
| 4 | **이슈·PR이 비어 있는지**(B) / 감사했는지(A) | 공개본에 옛 이슈 링크가 남아 깨져 있지 않은지 |

## 6. 경로 A — 그 자리에서 전환 (감사할 수 있을 때만)

`plans/release-runbook-v05.md`를 일반화한 요약이다. 단계별 상세·실제 명령·중단 조건은 거기를 본다.

| # | 단계 | 도구 | 비고 |
|---|---|---|---|
| A0 | 게이트: 워킹 트리 깨끗, 작업 브랜치는 전부 머지, 워커 워크트리 정리 | `git status` `git worktree list` | 진행 중인 작업이 있으면 시작 금지 |
| A1 | 치환표·mailmap 준비(프로젝트 고유 · **gitignore된 개인 파일**) | `replacements.example.txt` 복사 | 표가 없으면 여기서 멈춘다 |
| A2 | 워킹 트리 후보 스캔 → 표 확정 | `verify-tree.sh` | **이 단계 지나면 표를 바꾸지 않는다** |
| A3 | **미러 클론**에서 재작성(내용 + 커밋 메시지 + 신원을 **한 번에**) | `git filter-repo --replace-text --replace-message --mailmap` | 실 레포는 건드리지 않는다. 플래그를 따로 돌리면 중간 상태가 생긴다 |
| A4 | 재작성 검증 | `verify-history.sh` 「전체 통과」 + **3절 독립 스캔 (가)(나)** | 🔴 「전체 통과」만으로 끝내지 않는다 — 표 밖은 독립 스캔만 본다 |
| A5 | 이슈·PR·코멘트·릴리스·Actions 로그 감사 | `gh issue list --state all -L 1000 --json number,title,body,comments` · `gh pr list --state all -L 1000 --json number,title,body,comments,reviews` · `gh run list -L 100 --json databaseId,displayTitle` → `gh run view {id} --log` | 이슈 본문은 private 기간에 **검사된 적이 없다**(1절) — 각 본문을 `check-draft.sh`에 흘려 판정 |
| A6 | gh 계정·네트워크 확인 | `gh auth status --active` | 회사 계정이면 전환은 사용자가 직접 |
| A7 | 🔴 **force-push (되돌릴 수 없는 지점 1)** — `main`만 | `git push --force {원격} refs/heads/main:refs/heads/main` (`--mirror` 금지) | 실행 직전 A4 통과를 다시 확인. 실패하면 **재시도하지 말고 멈춘다** |
| A8 | 신원 연결 확인(잔디) | 5절 2번 | **공개 전환 전에.** 안 살아 있으면 공개 후에야 알게 된다 |
| A9 | 🔴 **공개 전환 (되돌릴 수 없는 지점 2)** | `gh repo edit {owner}/{repo} --visibility public --accept-visibility-change-consequences` | 되돌려도 이미 가져간 사본은 못 되돌린다 |
| A10 | 공개 후 확인 | 5절 | — |
| A11 | **로컬 레포를 공개본으로 교체** | 원본 보관 후 새로 클론 | 🔴 로컬 히스토리는 치환 전이다 — `push` 실패 메시지의 `pull --rebase` 안내를 따르면 치환 전 커밋이 공개 레포로 올라간다 |

### 되돌릴 수 없는 지점 (A)

| 지점 | 왜 | 실행 전 확인 | 중단 조건 |
|---|---|---|---|
| **A7 force-push** | 원격 히스토리가 교체된다. 되돌리기는 백업 미러로 다시 force-push하는 것뿐이고 그 사이 클론한 사람은 못 막는다 | A4 「전체 통과」+ 독립 스캔 판정 완료 · 대상 ref가 `main` 하나 | 인증·네트워크 오류 — 재시도 금지, 상태 확인 후 사람이 판단 |
| **A9 visibility 전환** | 공개되는 순간 불특정 다수가 클론·캐시·검색할 수 있다 | A8(신원 연결) 확인 · A5(이슈·PR 감사) 완료 | 계정이 의도한 소유자가 아니다 / A5가 안 끝났다 |

## 7. 흔한 함정 (유형)

| 유형 | 어디서 걸리나 | 막는 곳 |
|---|---|---|

# 🎖️ 팀장 패턴 — Claude Code 멀티 에이전트 팀 운영 체계

> 여러 Claude Code 세션을 "팀장 1 + 구현 팀원 N" 구조로 운영하는 재사용 가능한 워크플로우.
> 구축일: 2026-07-03 · 최초 적용: {app-repo} PROJ-591 (ARB 개선)

---

## 1. 개념

### 문제

대규모 개발 작업을 한 세션에서 하면 컨텍스트가 폭발하고, 여러 탭으로 나누면 사람이 **전령 역할**(브리프 복붙, 보고 복붙, 문서 갱신)을 떠안게 된다. 병렬 작업 시 TASKS/PROGRESS 문서를 여러 세션이 건드리면 충돌한다.

### 해결: 오케스트레이터 패턴

- **팀장 세션 1개**: 코드를 직접 쓰지 않고 방향·배분·검증·문서 현행화만 담당
- **구현 팀원 N개**: 배정된 태스크만 수행하고 정해진 양식으로 보고
- **허브 문서 단일 작성자**: TASKS.md/PROGRESS.md는 팀장만 수정 → 충돌 원천 차단

이 구조는 Anthropic이 정리한 멀티 에이전트 조정 패턴 중 **Orchestrator / Agent Teams 패턴**에 해당하며, Claude Code에 네이티브 기능(Agent Teams, experimental)으로도 존재한다.

### 참고 자료

- [Orchestrate teams of Claude Code sessions — 공식 문서](https://code.claude.com/docs/en/agent-teams)
- [Multi-agent coordination patterns — Anthropic](https://claude.com/blog/multi-agent-coordination-patterns)
- [How we built our multi-agent research system — Anthropic](https://www.anthropic.com/engineering/multi-agent-research-system)
- [Create custom subagents](https://code.claude.com/docs/en/sub-agents) · [Extend Claude with skills](https://code.claude.com/docs/en/skills)

## 2. 팀 구성 (포켓몬 네이밍 🔥)

| 이름 | 역할 | 성격/전문 | 권장 모델 |
|---|---|---|---|
| **팀장** | 오케스트레이터 | 방향성·목표 고민, 배분, 검증·피드백, 문서 현행화, 효율 개선 | Sonnet 4.6 (무거운 설계 판단만 Opus 4.8) |
| **파이리** 🔥 | 에이스 구현 | 가장 성실·실력파. 핵심 기능, 까다로운 슬라이스 | Sonnet 4.6 |
| **메타몽** 🟣 | 만능 구현 | 백엔드/프론트/테스트/문서 어디든 "변신". 병렬 보조 축 | Sonnet 4.6 / 분석은 GLM |
| **꼬부기** 💧 | UX/디자인 (예정) | 디자인 툴·UI/UX 전문 | 미정 |

### 팀장의 원칙

1. **소스 파일 직접 수정 금지** — 코드는 팀원이 쓴다
2. **허브 문서(TASKS/PROGRESS) 단일 작성자** — 팀원은 읽기 전용
3. **보고는 git으로 검증** — `git log`/`git show --stat`/grep으로 교차검증 후 체크
4. **체크포인트는 팀원에게 명령**, 결과만 받아 확인
5. **읽기 2티어** — 실시간 판단은 git log + 보고, 문서 전체 읽기는 시작 1회 + 체크포인트만

## 3. 파일 구조

```
~/.claude/skills/teamleader/        ← 글로벌 (모든 프로젝트 재사용)
├── SKILL.md            /teamleader 로 팀장 활성화 — 역할·원칙·운영 루프
├── ways-of-working.md  팀 규칙 (팀장이 성찰·업데이트)
├── model-guide.md      멀티 프로바이더 모델 배분 가이드 (주기 현행화)
├── roster.md           팀원 명부 + 추가 절차
└── skill-guide.md      역할×시점 스킬 사용 매핑 (팀장/팀원 어떤 스킬을 언제)

~/.claude/skills/pairi/             ← 파이리 세션 시작 스킬
└── SKILL.md            /pairi 로 파이리 정체성 로드 + 기력회복 후 브리프 대기

~/.claude/skills/metamong/          ← 메타몽 세션 시작 스킬
└── SKILL.md            /metamong 으로 메타몽 정체성 로드 + 기력회복 후 브리프 대기

~/.claude/agents/                   ← 팀원 정의 (subagent/teammate/탭 공용)
├── pairi.md            파이리 페르소나·규율·보고 양식
└── metamong.md         메타몽 페르소나·규율·보고 양식

{프로젝트}/.claude/                  ← 프로젝트별 상태
├── TASKS.md            태스크 목록 (팀장 단일 작성자)
├── PROGRESS.md         진행 상황 (팀장 단일 작성자)
└── team/reports/
    ├── pairi.md        파이리 보고 로그 (파이리만 수정, 최신이 위)
    └── metamong.md     메타몽 보고 로그 (메타몽만 수정)
```

**설계 포인트**: 팀원 정의를 `~/.claude/agents/`에 한 번 두면 ① 탭 모드 브리프 ② 일반 subagent ③ 네이티브 팀 teammate — 3가지 방식에서 모두 재사용된다.

**팀원 추가 절차**: ① `~/.claude/agents/{name}.md` 생성 (페르소나+규율+보고 양식) → ② `~/.claude/skills/{name}/SKILL.md` 세션 시작 스킬 생성 → ③ `roster.md`에 행 추가 → ④ 프로젝트에 `.claude/team/reports/{name}.md` 스켈레톤 생성

## 4. 운영 모드 2가지

### 모드 A: 탭 모드 (operator pattern) — 현행 기본

사용자가 터미널 탭을 열어 팀원 세션을 직접 실행.

- **팀원 세션 기동**: 해당 탭에서 `/pairi` 또는 `/metamong` 입력 → 정체성 로드 + 기력회복(보고 이력→TASKS/PROGRESS→git) 후 브리프 대기
- 팀장이 **자기완결 브리프** 작성 → 사용자가 해당 탭에 붙여넣기
- **컨펌 신호 프로토콜**(2026-07-12): 팀원은 커밋 전 `.claude/team/confirm/{이름}.request.md`에 테스트 플랜을 담아 컨펌 요청 → 팀장이 백그라운드 감시로 감지, git 교차검증 후 사용자에게 제시 → 사용자가 팀장 세션에서 테스트·판단 → 팀장이 `{이름}.reply.md`(APPROVE/FIX) 작성 → 팀원이 백그라운드로 감지해 커밋 또는 보완. 규약 상세는 ways-of-working.md
- 보고: 팀원이 `.claude/team/reports/{이름}.md`에 기록 (+채팅 출력) → 팀장이 읽고 허브 문서 반영
- ✅ 안정적, 탭별 완전 제어, **프로바이더 혼용 가능** (탭마다 use-glm/use-claude)
- ❌ 사람이 브리프 전달 담당 (컨펌·보고 전달은 신호 프로토콜로 자동화됨)

**세션 수명주기**: 태스크마다 clear하지 않는다 — 같은 도메인 연속 태스크는 쌓인 컨텍스트가 자산. 리셋(새 세션·`/clear`) 기준:
1. **도메인 전환** — BE↔FE 등 이전 맥락이 무관할 때 (오히려 오염 방지)
2. **컨텍스트 잔량 ~20% 이하** — 대형 태스크 도중 방전 방지를 위해 착수 *전에* 선제 리셋
3. **대형(M+) 태스크 착수 직전** — 여유 컨텍스트 확보

리셋 후엔 `/pairi` / `/metamong`로 기력회복하면 이어진다. **세션=소모품, 상태=파일** (정체성/보고 이력/허브 문서/git이 연속성 보장).

> 🍬 **용어: 기력회복** — 기절(리셋)한 포켓몬을 기력의조각으로 되살리듯, 새 세션이 상태 파일(정체성→보고 이력→TASKS/PROGRESS→git)을 읽어 이전 맥락을 복원하는 절차. (구 용어: 재수화)

### 모드 B: 네이티브 팀 모드 (Agent Teams, experimental)

`settings.json`에 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` 설정 필요.

- 팀장이 직접 팀원 스폰: *"pairi 타입으로 '파이리' 이름의 팀원 스폰해서 Task 12"*
- **공유 태스크 리스트**: 의존성 자동 추적 + 파일락 클레임 (경합 방지)
- **자동 보고**: 팀원 메시지 자동 배달 + idle 알림 → 복붙·보고 파일 불필요
- agent 패널에서 팀원 선택해 직접 대화/개입 가능, 권한 승인은 팀장 세션으로 집결
- ❌ experimental 한계: `/resume` 시 팀원 미복원, 태스크 상태 갱신 lag 가능, **팀원이 리드 env 상속 → 프로바이더 혼용 불가**

> 💡 **전환 전략**: 안정성이 중요한 작업은 탭 모드, 위험 낮은 작업부터 네이티브 팀 시험 → ways-of-working.md에 회고 누적하며 안정화.

### 세 가지 실행 방식 비교

| | 탭 | subagent | teammate (네이티브 팀) |
|---|---|---|---|
| 띄우는 주체 | 사람 | 팀장 세션 | 팀장 세션 |
| 작업 중 대화 | 해당 탭에서 직접 | 불가 (결과만 반환) | 팀장에게 질문 + 사용자 직접 개입 가능 |
| 보고 | 신호 파일 + 백그라운드 감시로 자동 (컨펌 신호 프로토콜) | 자동 1회 | 자동 수시 |
| 세션 지속 | 유지·재개 가능 | 일회성 | 세션 내 지속, resume 불가 |

## 6. 팀 운영 규칙 (ways-of-working 요약)

### 보고 양식 (필수)

```
[커밋 SHA] + 한일 3줄 + 다음 의존성 풀림/막힘
```

양식 미준수 시 팀장이 재요구. 막힘 보고에는 원인 + 시도한 것 + 필요한 결정 포함.

### 팀원 작업 규율

- 브리프에 배정된 태스크만 하고 **멈춘다**
- **자기 파일 경로만 `git add`** — `git add -A` 금지 (같은 워킹트리 공유)
- 커밋 전 테스트/빌드/린트 필수
- 커밋 메시지: 한글 + Conventional Commits + Jira 티켓. **Co-Authored-By 금지**
- 슬라이스 절차: ①사전 설명 ②코드 전부 읽기 ③계획 ④구현 ⑤검증 ⑥커밋 ⑦보고

### 팀장 운영 루프

```
배분 (의존성 확인, 파일 경로 안 겹치게, 모델 권장 포함)
  → 보고 수령 (양식 검사)
  → git 교차검증
  → TASKS [x] + 커밋 SHA 메모
  → 다음 배분
체크포인트마다: 소스 검토 + ways-of-working/model-guide/roster 성찰
```

- 런타임 검증(LLM 실연, 외부 연동)은 **사용자 직접 확인 항목**으로 분리해 안내

## 7. 모델 배분 가이드 (멀티 프로바이더)

### 프로바이더 전환 (환경 고유)

`~/.zshrc`의 셸 함수로 **세션(탭) 단위** 전환:
- `use-glm` → z.ai Anthropic 호환 엔드포인트 + 티어 매핑 (haiku→glm-4.7, sonnet→glm-5.1[1m], opus→glm-5.2[1m])
- `use-claude` → 기본 Anthropic

### 역할별 배분

| 역할 | 1순위 | 비고 |
|---|---|---|
| 팀장 (오케스트레이션) | Sonnet 4.6 | 리드 상위 + 워커 Sonnet = 전원 Opus 대비 ~40% 절감 |
| 구현 워커 | Sonnet 4.6 | 대부분의 구현 기본값 |
| 고난도 설계·디버깅 | Opus 4.8 | 최고난도 장기 자율 작업만 Fable 5 |
| 분석·탐색·대량 조사 | GLM (glm-5.1) | Claude 쿼터 절약 (기존 관례: 분석=GLM) |
| 단순 반복 | Haiku 4.5 or glm-4.7 | 쿼터 상황 따라 |

### 새 프로바이더 추가 (확장)

1. `~/.zshrc`에 `use-{이름}()` 함수 추가 (use-glm 패턴 복사: AUTH_TOKEN + BASE_URL + 티어 매핑)
2. model-guide.md에 프로바이더 섹션 추가
3. 역할별 배분표 갱신 → 사용 경험 축적 후 "관측 특성" 업데이트

### 현행화

팀장이 30일 주기 or 새 모델 소식 시: Anthropic 공식 문서(`/claude-api` 스킬) + z.ai pricing + Artificial Analysis/LMArena/SWE-bench.

## 8. 사용법 (Quick Start)

### 새 작업 시작

1. **팀장 세션** → `/teamleader` (roster·규칙·모델가이드·스킬가이드 로드 → 프로젝트 상태 파악 → 배분안 보고)
2. **탭 모드**: 탭 열기 → 프로바이더 설정(`use-glm`/`use-claude` + `/model`) → **`/pairi` 또는 `/metamong`** → 기력회복 완료 후 팀장 브리프 붙여넣기
   **팀 모드**: "파이리 스폰해서 Task N" 지시
3. 보고 오면 팀장이 git 교차검증 → TASKS 갱신 → 다음 배분

### 세션 관리

| 상황 | 동작 |
|---|---|
| 팀장 세션 마무리 | `/save-progress` |
| 새 팀장 세션 시작 | `/teamleader` → PROGRESS/TASKS/git 읽고 이어서 |
| 팀원 탭 리셋 후 재개 | `/pairi` 또는 `/metamong` → 기력회복 → 브리프 대기 |
| 전체 현황 확인 | `/progress-check` |
